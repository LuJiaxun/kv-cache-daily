一、互联与内存池

1. A Photonic-CXL Memory Appliance for Scalable KV Cache Management in LLM Inference

  • 链接：https://arxiv.org/abs/2607.27187
  • 时间：2026-07-29
  • 方向：光子互联 · CXL 内存池 · 淘汰悬崖

摘要：规模化推理撞上内存墙：KV 需要几十 TB 容量、几百 GB/s 带宽，而现有内存层级无法同时提供。作者在多代 GPU、多种 LLaMA 模型上做刻画，发现从 host memory 取回 KV 相比重算最多快 100×，但只能支撑几十个并发长上下文用户；电交换 CXL 池化理论上能补上这个缺口，却受交换机 70–500ns 的每跳延迟、米级线缆距离和超线性功耗限制，做不到实用的 TB 级部署。论文提出 Marvell Photonic Fabric Memory Appliance：用无源光纤 shuffle 替代电交换机，以无交换的全交叉拓扑在 16 台主机间提供 32TB 共享内存。仿真显示相比电交换 CXL 池延迟降低 50% 以上，多轮对话场景下 TTFT 改善 6.6×，并消除了缓存淘汰悬崖。

对广域的启示：跨节点取 KV 的瓶颈正从“网络带宽”转向“互联介质”。把 KV 池做进 CXL + 光互联，等于把“跨机”变成“跨内存层级”；对广域而言，这提示近域用光互联池化、远域才走 WAN的分层思路。

2. A CXL Memory Rack for Multi-Turn LLM Serving

  • 链接：https://arxiv.org/abs/2607.18141
  • 时间：2026-07-20
  • 方向：CXL 混合内存 · 机架级 KV 复用 · 前缀预取

摘要：长上下文、多轮、agent 负载反复复用已处理上下文，KV 复用把瓶颈转移到“存储与服务可复用 KV 状态”的内存层；GPU HBM 与 host DRAM 都太贵，撑不起 TB 级共享上下文容量。HyMCache 用成本友好的 CXL-hybrid memory（CXL-HM）搭内存机架：设备内少量 DRAM + 大容量 SSD，两者都在 CXL 接口之后。它利用多轮 KV 访问“读为主、可预测、只追加”的特性重构 CXL-HM 内的 DRAM 管理，用请求级前缀预取和机会式写缓冲把延迟关键的读暂存到设备 DRAM，从而以 SSD 的成本获得接近 DRAM 的 KV 复用效率。真实 CXL-HM 原型上，同 DRAM 预算下比本地 LMCache 快 3.0×（单机）、1.45×（PD 分离）；与 1TB 分布式 DRAM 的 Mooncake 相比性能低约 30%，但 DRAM 用量少 16×。

对广域的启示：这是“用便宜介质换容量”的典型——广域 KV 缓存池同样需要分级（DRAM/SSD/远端），关键是识别出访问模式（只追加、可预测）来提前搬运，而不是被动命中。

3. SAC: Disaggregated KV Cache System for Sparse Attention LLMs with CXL

  • 链接：https://arxiv.org/abs/2606.19746
  • 时间：2026-06-18
  • 方向：稀疏注意力 · 分离式缓存 · 按需取 top-k

摘要：长上下文把瓶颈从算力转向内存容量；传统方案用 RDMA 分离式内存池，但它是粗粒度的：解码前要把整段 prefix KV 从远端取回本地。对新兴的稀疏注意力模型这非常不划算——解码时只有一小部分 KV 条目是活跃的，却仍然全量搬运，造成严重传输瓶颈与本地内存浪费。SAC 是首个为稀疏注意力优化的分离式 KV 系统：利用 CXL 的低延迟、cache-line 粒度 load/store 语义，在推理过程中按需只取 top-k 所需 KV 条目。DeepSeek-V3.2 + SGLang 上相比 RDMA 基线吞吐 2.1×、TTFT 低 9.7×、TBT 低 1.8×。

对广域的启示：取数粒度决定传输成本。当模型本身稀疏时，“按需取 cache line”比“预取整段前缀”更省；跨广域时如果无法做到 cache-line 粒度，至少应把粒度对齐到活跃 token 集合。

二、调度与预取

4. OrbitFlow: SLO-Aware Long-Context LLM Serving with Fine-Grained KV Cache Reconfiguration

  • 链接：https://arxiv.org/abs/2601.10729
  • 时间：2026-01-05
  • 方向：SLO 保障 · 逐层驻留 · 动态重配置

摘要：长上下文服务中请求长度与 batch 组成在生成过程中不断变化，显存占用随之剧烈波动；把 KV 卸载到 host memory 能限制有效内存占用，但现有静态/预定的卸载策略无法跟上这种快速变化，导致过多的 CPU→GPU KV 搬运，表现为延迟尖峰与频繁的 SLO 违约。OrbitFlow 是细粒度自适应 KV 管理：用轻量 ILP 求解器在内存约束下决定每个请求哪些层的 KV 留在 GPU，并在生成过程中依据运行时反馈持续修正放置；重载时启用回退机制，临时推迟占用大的在飞请求，保住整体 SLO 达成率。实验显示 TPOT 与 TBT 的 SLO 达成率分别提升最多 66% 和 48%，p95 延迟降低 38%，吞吐相比现有卸载方法最高 3.3×。

对广域的启示：“留哪些层在本地”是一等决策变量。跨域场景同理：不必全量拉回，可以按 SLO 逐层决定哪些层必须本地、哪些层可按需远端取。

5. Learning Agent Execution for KV-Cache Management in Agentic Serving

  • 链接：https://arxiv.org/abs/2608.14624
  • 时间：2026-07-16
  • 方向：Agent 语义 · 在线学习 · 主动预取

摘要：多 agent 系统把用户请求拆成一系列专用 agent，每个 agent 反复执行固定上下文（system prompt、工具定义、few-shot），复用机会很大；但现有系统用前缀缓存 + 最近使用替换这类反应式策略，可复用的 agent 上下文常在下次调用前就被驱逐，被迫重算。CacheScout 的核心洞察是：未来的 KV 复用由 agent 执行语义决定，而不只是缓存新近度；它在线学习 agent 之间的执行转移（不需要预定义工作流图，也不需要离线训练），用学到的执行模型同时指导淘汰与主动预取，且不改变服务关键路径。在 vLLM 上，真实多 agent 负载的 KV 命中率提升 10–18 个百分点，平均 TTFT 降 18–45%，每轮延迟降 29–38%，峰值吞吐最高 +57%；换更大模型仍能把 TTFT 降最多 54%、吞吐 +37%。

对广域的启示：预测“下一个 agent 要用什么”比缓存最近用过的更有价值；广域预取若能拿到工作流语义，就能把 WAN 传输提前到空闲窗口。

6. DualDecoder: Accelerate Long Context LLM Inference by Predictive Prefetch

  • 链接：https://arxiv.org/abs/2607.26475
  • 时间：2026-07-29
  • 方向：推测预取 · 辅助状态开销 · 高并发

摘要：长上下文推理面临内存墙：KV 随上下文与并发线性增长。现有稀疏 KV 方法把大部分条目卸载到 host memory、每步只取关键条目，但它们在 GPU 里引入了大量用于检索管理的辅助状态；实测表明这些常被忽视的辅助状态带来显著内存开销，在高并发下反而成为新瓶颈。DualDecoder 的洞察是：下一个 token 解码所需的关键 KV 条目可以由前一个推测 token 准确预测，因此取数可以提前预取并与解码计算重叠，从而消除辅助状态带来的 GPU 内存开销。它用双 token 解码流水线以极小开销识别关键 KV，配合层感知传输调度与层作用域内存管理，解码吞吐相比 SOTA 最高 2.62×，同时保持延迟与模型质量。

对广域的启示：预取精度本身就是一种压缩——预测得准，就不需要为“可能的命中”预留大量元数据；跨域场景里，元数据开销往往被忽视，却会决定预取是否划算。

7. PrefillShare: A Shared Prefill Module for KV Reuse in Multi-LLM Disaggregated Serving

  • 链接：https://arxiv.org/abs/2602.12029
  • 时间：2026-02-12
  • 方向：多模型共享 · prefill 解耦 · PD 分离

摘要：多 agent 系统常用多个专用模型处理同一段共享上下文，每个模型都重复执行 prefill 并各自维护 KV，推高聚合 prefill 负载，并通过加剧 prefill-decode 干扰恶化尾延迟；PD 分离能缓解干扰，但并不能消除模型间的计算与 KV 存储冗余。PrefillShare 把模型分解为 prefill 模块与 decode 模块，冻结 prefill 模块、只微调 decode 模块，于是多个任务专用模型可以共享同一个 prefill 模块，以及为同一 prompt 生成的同一份 KV cache；同时在 vLLM 分离式系统上引入路由机制，让 prefill 共享真正生效。多种任务与模型上匹配全量微调精度，多模型 agent 负载下 p95 延迟低 4.5×、吞吐高 2.0×。

对广域的启示：共享 prefill 等于共享传输——同一份 KV 只生成一次、只搬一次，多模型分头 decode。这比“每个模型各传一份”在广域链路上省下的带宽是线性的。

三、压缩

8. OScaR: The Occam's Razor for Extreme KV Cache Quantization in LLMs and Beyond

  • 链接：https://arxiv.org/abs/2605.19660
  • 时间：2026-05-19
  • 方向：INT2 量化 · token 范数失衡 · 旋转+缩放

摘要：长上下文与多模态让 KV 成为部署的主要内存瓶颈。逐通道量化能处理 Key 张量固有的通道级离群值，但在极端压缩下效果明显下降。论文从经验与理论两侧重新审视逐通道范式，指出 Token Norm Imbalance（TNI） 是量化保真度的主要瓶颈：当共享量化参数需要覆盖范数差异巨大的 token 组时，TNI 会系统性放大误差。于是提出 OScaR（Omni-Scaled Canalized Rotation）：在逐通道范式基础上，用通道化旋转（Canalized Rotation） 加 全 token 缩放（Omni-Token Scaling） 高效抑制 TNI 引起的序列维方差，并配套优化系统设计与 CUDA kernel。在文本、多模态、全模态 X-LLM 上一致优于现有方法，INT2 下接近无损；相比 BF16 FlashDecoding-v2，解码最高 3.0× 加速、内存降低 5.3×、吞吐 4.1×。

对广域的启示：INT2 近无损意味着传输字节可以再降一个量级；TNI 这个诊断也提醒：量化误差的来源是 token 间范数差异，而这在长上下文跨域传输里更普遍。

9. ValueDiff: Value-Geometric KV Cache Eviction for Sink-Suppressed LLMs

  • 链接：https://arxiv.org/abs/2609.23314
  • 时间：2026-09-20
  • 方向：值几何 · 驱逐信号 · 无 sink 模型

摘要：采用 QK-normalization、门控注意力、可学习 attention sink 或 logit softcapping 的现代 LLM，持久注意力 sink 更弱，而现有 KV 驱逐方法主要依赖 sink。论文观察到：在这些模型上，sink 越弱，value 向量相对 key 向量的离散度越大。ValueDiff 据此提出值几何驱逐——按 token 的 value 向量相对缓存均值的 L2 偏离排序；在“未来注意力最大熵”假设下，同一分数恰好是最小扰动驱逐的解。它在 prefill 的每个 block 边界与 decode 的每一步都执行驱逐：RULER 2k 预算下七个 sink-suppressed 模型保留 88–99% 稠密性能（6/7 最优）；LongBench 4k 预算下平均保留 92%（最强基线 83%）；MATH-500 的 25% 预算下在每个 sink-suppressed 模型上都是最强非稠密方法，门控注意力模型上最多领先约 20 分。

对广域的启示：驱逐信号要跟着架构走——当 key 侧信号变弱时，value 几何更可靠。对跨域缓存，这意味着同一套驱逐策略不能跨模型族通用，需要按架构校准。

10. Page-EntroKV: Hardware-Aligned, Entropy-Weighted KV-Cache Eviction under Grouped-Query Attention

  • 链接：https://arxiv.org/abs/2610.03135
  • 时间：2026-10-02
  • 方向：GQA 组粒度 · 熵加权 · 页对齐

摘要：多数动态驱逐方法按查询头打分、独立选 token，这与 GQA 的实际分配方式不符：多个查询头共享一份物理 KV 缓冲，各自独立的选择会迫使引擎保留它们选择的并集，最多把缓存膨胀到组比 r 倍；而算术平均池化又会稀释承载事实召回的专用检索头。Page-EntroKV 在 GQA 真正分配的粒度上做驱逐：组内头用sink 隔离的碰撞熵（Rényi-2） 导出权重（每个头一次内积，prefill 时算一次，无需校准），使 sink 头无法伪装成检索头；池化分数投影到 PagedAttention 的页框，驱逐在（层、组、页）的硬件元组上执行。论文形式化了并集开销比（UOR） 与组内分歧，证明两者在双头组上的恒等关系及任意组比下的双侧界，证明严格预算保持与有限上下文 needle 保留界（算术平均池化可证违反）。Qwen2.5-1.5B（r=6）上，2% 预算时头独立回放的并集开销高达 4.75×，而 Page-EntroKV 保持 UOR 恰为 1.000；sink 隔离消除了 13× 的 sink 伪装；20% 预算下 needle 召回 100%，均值池化为 0%。

对广域的启示：压缩必须对齐硬件的实际存储粒度。GQA 下按头独立驱逐会造成“并集膨胀”，跨域传输时这部分是纯粹浪费的字节；页对齐的驱逐能保证预算与字节数真实可控。

今日观察

  1. 互联介质在换代：光子 CXL（32TB/16 主机、延迟 -50%、TTFT 6.6×）与 CXL-HM 机架（DRAM 用量 -16×）说明，“池化 KV”的物理基础正在从 RDMA 网络转向内存语义互联。
  2. 取数粒度比取数量更重要：SAC 只取 top-k、OrbitFlow 逐层决定驻留、DualDecoder 预测下一步所需——三者都在减少无效搬运。
  3. 共享是最高效的复用：PrefillShare 让多个模型共用一份 prefill 与 KV，等于把跨域带宽需求按模型数摊薄。
  4. 压缩在向两个极端走：INT2 近无损（OScaR）与更聪明的驱逐（ValueDiff/Page-EntroKV）同时推进，但都强调“按架构与硬件校准”。
