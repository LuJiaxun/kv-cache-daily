一、跨广域 / 跨机房传输

1. Prefill-as-a-Service: KVCache of Next-Generation Models Could Go Cross-Datacenter

  • 链接：https://arxiv.org/abs/2604.15039
  • 时间：2026-04（arXiv v2）
  • 方向：跨机房 PD 分离 · KV 广域传输 · 模型架构与传输可行性的关系

摘要：论文提出 “Prefill-as-a-Service”（预填即服务）的部署形态：把计算密集的 prefill 集中到少数机房，把 decode 放到离用户更近的边缘机房，中间跨广域网传输 KV Cache。它指出跨机房 KV 传输是否划算，不只取决于网络带宽，还取决于模型架构决定的 KV 尺寸——下一代线性/混合线性注意力模型的 KV（或循环状态）随上下文增长远慢于标准 Transformer，使“跨机房搬运上下文状态”第一次具备经济性。论文给出了 prefill 吞吐与输出带宽之间的配比关系（用 prefill 时间与单请求 KV 大小的期望值来估算所需出口带宽），用于判断机房比例与何时该跨域。公开解读称其带来约 54% 的推理吞吐提升（口径待原文核对）。

对广域的启示：这是“用模型架构换网络带宽”的思路——广域 KV 传输的可行性边界会随模型从 full attention 转向线性注意力而整体外移；做跨域调度时，应把“单位 token 的 KV 字节数”作为一等参数，而不是假设它固定。

2. KVCompass: A Discovery Plane for Internet-Scale Prefix Cache Sharing in LLM Serving

  • 链接：https://arxiv.org/abs/2610.24179
  • 时间：2026-10
  • 方向：互联网级前缀缓存 · 缓存发现/索引 · 跨区域路由

摘要：论文关注“互联网规模”的前缀缓存共享：当大量区域各自持有可复用的前缀 KV 时，一个请求该去哪里取、取得到与否，取决于能否发现其他区域的前缀分布。KVCompass 设计了一个发现平面（discovery plane），为各区域的 worker 提供前缀可用性查询与打分，并处理边缘节点只有局部视图、全局索引存在滞后与不完整的问题。它把“缓存命中”从单机/单集群问题扩展为跨区域的索引与路由问题，让请求在传输前就能判断复用是否值得。

对广域的启示：广域复用 = 发现问题 + 传输问题。只优化压缩/带宽，而不知道该去哪儿取，仍然会退化成跨域重复 prefill；“查得到”与“传得回”必须一起设计（索引新鲜度、探测开销、命中率-时延权衡）。

3. WAN Cache: Wide-Area Multi-Tier KV Cache Based Inference Acceleration Networks

  • 链接：https://ieeexplore.ieee.org/document/11716601
  • 时间：2026（IEEE，文献号 11716601）
  • 方向：广域多级 KV 缓存 · 热度驱动同步 · 时延约束检索

摘要：论文把 KV Cache 当作可在广域范围内多级缓存的“内容”，构建面向推理加速的广域缓存网络。其调度包含两条主线：热度驱动的层间同步（把热点 KV 从下层/远端提升到更近的层级）与时延约束下的分层检索（在满足 TTFT/SLO 的前提下选择从哪一层取）。论文同时给出了推理实例写入缓存池、以及从缓存池读回实例这两侧的决策机制，并用实验室与现网测试评估广域传输表现。

对广域的启示：KV 缓存可以借鉴 CDN 的“热度 + 分层 + 时延约束”方法论；关键不是“缓存所有 KV”，而是用热度预测决定哪些 KV 值得占用广域带宽去同步，以及读路径上每一层的最晚可接受时延。

4. RTT- or Bandwidth-Bound? Demystifying the KV Cache Transfer in Large Language Model Serving

  • 链接：https://dl.acm.org/doi/10.1145/3748273.3749196
  • 时间：2025（ACM NetAI Workshop @ SIGCOMM'25）
  • 方向：KV 传输性能刻画 · RTT vs 带宽 · PD 分离

摘要：论文针对“KV Cache 传输慢是因为带宽不够”这一常见假设做拆解，通过测量与建模分析 KV 传输究竟在什么时候受 RTT/往返时延与协议开销限制、什么时候受有效带宽限制。不同模型规模、并行配置、KV 布局与网络条件下，瓶颈归属会变化；把两者混为一谈会导致优化方向错误（例如在 RTT-bound 场景一味加带宽收效甚微）。论文据此给出面向 PD 分离部署的传输与调度建议。

对广域的启示：这是做广域 KV 优化前的“体检表”。RTT-bound 时优先做流水线/批量/连接复用/预取（把往返次数降下来）；bandwidth-bound 时优先做量化/稀疏/驱逐（把字节数降下来）。先判瓶颈，再选武器。

5. ShadowServe: Interference-Free KV Cache Fetching for Distributed Prefix Caching

  • 链接：https://arxiv.org/abs/2509.16857
  • 时间：2025-09
  • 方向：分布式前缀缓存 · KV 取数 · 干扰消除

摘要：在分布式前缀缓存中，命中后要把远端 KV 取回本地，这一过程会与本地 prefill/decode 争抢网络带宽、PCIe 拷贝和内存，造成尾延迟与抖动。ShadowServe 提出无干扰的 KV 取数：让远端取数与本地计算重叠，避免阻塞关键路径，并用最小拷贝（minimal-copy）的内存管理减少数据在层级间的搬移次数。其目标是让“缓存命中”真正转化为时延收益，而不是把排队从计算侧转移到传输侧。

对广域的启示：广域取数要把传输隐藏在计算后面（预取、流水线、零拷贝/最小拷贝）；同时要控制“取数风暴”——大量请求同时命中远端时的拥塞会让收益反转。

二、KV 池化与系统底座

6. Mooncake: A KVCache-centric Disaggregated Architecture for LLM Serving

  • 链接：https://arxiv.org/abs/2407.00079 ｜ ACM TOS: https://doi.org/10.1145/3773772
  • 时间：2024-06 预印本；FAST'25；ACM TOS 2026
  • 方向：PD 分离 · KV 池化 · 传输引擎

摘要：Mooncake 是面向长上下文、高负载 LLM 服务的 KVCache-centric 分离式架构：prefill 与 decode 解耦，KV Cache 不再只躺在单卡 HBM，而是进入由 DRAM/SSD 等组成的分层缓存池，由全局调度器（Conductor）按 KV 复用潜力与负载做请求编排，并配套高性能传输引擎在实例与缓存池之间搬运 KV。它把“KV 的放置、复用、搬运”提升为系统的一等资源，而不是计算的附属品，已在 Kimi 的生产流量中验证。

对广域的启示：广域场景可直接复用其抽象——KV 是有地址、有生命周期、可调度的对象；把传输引擎、缓存层级、调度器解耦，才可能把 LAN 内的池化扩展到 WAN。

三、复用

7. Stateful Large Language Model Serving with Pensieve

  • 链接：https://arxiv.org/abs/2312.05516
  • 时间：EuroSys 2025
  • 方向：有状态服务 · 前缀/部分 KV 复用 · 合批

摘要：Pensieve 针对“无状态请求-响应”造成的重复 prefill：它让服务端有状态地保留历史请求的 KV，当新请求与已有请求共享前缀（甚至只共享部分前缀）时，复用已算好的 KV，并把新请求与处于 prefill 阶段的请求合批，用剩余算力补齐未命中的部分。这样复用不必以“完全相同的 prefix”为前提，也能在多轮对话、模板化 prompt 等场景显著减少重复计算。

对广域的启示：最好的跨域传输是“不用传”——能在本地/近端复用的 KV 就不要跨域搬。设计广域系统时，应先把复用做到极致，再把剩下的未命中流量交给传输层优化。

四、压缩

8. CacheGen: KV Cache Compression and Streaming for Fast Large Language Model Serving

  • 链接：https://arxiv.org/abs/2310.07240
  • 时间：SIGCOMM 2024
  • 方向：KV 压缩 · 流式传输 · 带宽自适应

摘要：CacheGen 把 KV Cache 当成一种需要“编码-传输-解码”的数据对象：先用增量编码、量化与算术编码把 KV 张量压成紧凑的比特流，再按当前可用带宽自适应地分段流式传输，让解码端边收边解、边恢复 KV，而不必等整个 KV 传完才开始计算。公开结果显示其可把包含网络与计算延迟的 TTFT 降低 3.1–4.7×。它把“压缩率”和“传输调度”放在同一个优化问题里，而不是各自独立优化。

对广域的启示：广域高时延、带宽波动的环境下，压缩 + 流式 + 带宽自适应是基本组合拳；关键是让压缩粒度与流式分块对齐，避免“为了解压而等待”。

9. RateQuant: Optimal Mixed-Precision KV Cache Quantization via Rate-Distortion Theory

  • 链接：https://arxiv.org/abs/2605.06675
  • 时间：2026-05
  • 方向：混合精度量化 · 率失真 · 位宽分配

摘要：混合精度 KV 量化的核心难题是“给哪些层/头/通道分配多少 bit”。RateQuant 用率失真理论把位宽分配建模为在给定比特预算下最小化重建/输出失真的优化问题，推导出各部分的边际收益并据此分配精度，而不是靠均匀位宽或启发式规则。这样在相同显存（或相同传输字节）预算下能获得更低的量化误差。

对广域的启示：量化本质上是在用比特换失真，而广域传输是在用字节换时间——率失真框架可以直接回答“砍掉多少字节、掉多少精度”，适合做跨域传输前的自适应压缩决策。

10. DropKV: Decoupling Residual-Output Perturbation for Near-Optimal KV-Cache Eviction

  • 链接：https://arxiv.org/abs/2610.22130
  • 时间：2026-10（检索显示 ICML/NeurIPS 2026 收录信息不一致，以原文为准）
  • 方向：KV 驱逐 · 输出扰动估计

摘要：KV 驱逐的常见做法是用注意力分数等代理指标判断 token 重要性，但这些指标与“删掉它最终会让输出偏多少”并不等价。DropKV 把残差-输出扰动从代理分数中解耦出来，直接估计每个 KV 对被驱逐后输出的影响，并据此做近最优的驱逐决策。它试图回答的不是“这个 token 被关注得多不多”，而是“删掉它，最终结果会坏多少”。

对广域的启示：驱逐直接减少需要缓存和传输的 token 数，且与量化正交、可叠加；对广域而言，“按输出影响驱逐”比“按注意力分数驱逐”更贴近端到端质量约束。

今日观察

  1. 2026 年的新变量是“模型架构”：线性/混合线性注意力让跨机房搬运 KV 从“不划算”变成“可讨论”，Prefill-as-a-Service 是代表。
  2. 广域复用正在从“单集群前缀树”走向“互联网级发现平面”：KVCompass 说明索引与路由会成为独立的一层。
  3. 传输优化的顺序应是：先判瓶颈（RTT vs 带宽）→ 再压缩（量化/驱逐）→ 再调度（流式/预取/分层），而不是默认“带宽不够就压缩”。
  4. 经典工作仍是底座：Mooncake 的池化抽象、Pensieve 的复用、CacheGen 的压缩流式，构成了今天广域方案的三块积木。
