一、重点方向：状态接口与陈旧缓存语义（3 篇）

1. Specialized Large Language Models for Markovian Reasoning: Structural Cache Compression, Transition Pretraining, and Dual-Loop Transformers

  • 链接：https://arxiv.org/abs/2611.28285
  • 时间：2026-11-20
  • 方向：常数状态接口 · 结构缓存压缩 · 双环 Transformer

摘要：标准自回归 LLM 要关注不断增长的历史 token，使 KV cache 成为长链推理与多分支采样中的核心内存与吞吐瓶颈。但有一类重要的推理问题天然是一阶马尔可夫的：下一步只依赖对当前状态的一个充分表示，而不依赖此前所有步骤的原始序列。论文由此提出一套面向马尔可夫推理专用 LLM 的统一设计范式。在缓存层面，马尔可夫状态接口把依赖历史的 KV 存储转换为相对于推理步数而言常数大小的状态传输；配套还有转移预训练（让模型学会状态到状态的转移）与双环 Transformer 架构（外层环负责状态推进、内层环负责步内计算）。

对广域的启示：这是"传状态而不是传历史"最彻底的一种形式——如果任务确实是马尔可夫的，跨节点只需要同步一个常数大小的状态，带宽与上下文长度解耦。对跨域 agent 编排，这条思路的关键不在压缩算法，而在任务是否允许把历史折叠成状态：允许则传输量恒定，不允许则无论怎么压都会随长度涨。

2. The Old Scene Lives in the Cache: Diagnosing and Shedding Stale History in Streaming Video Generation

  • 链接：https://arxiv.org/abs/2611.32116
  • 时间：2026-11-24
  • 方向：陈旧缓存 · 主体保留 vs 场景更新 · 免训练

摘要：流式视频生成在切换场景同时保留原始主体时存在一个冲突：缓存的历史既帮助维持主体，又持续保留应当消失的旧场景物体。论文通过对文本条件、去噪步、局部窗口与注意力 sink 的受控干预，定位了缓存视觉历史如何留住这些过时内容：只要原始帧仍在缓存里，KV flush 与 sink 重算仍会让旧场景物体出现在生成视频中。把这段历史替换成目标场景历史能基本去掉这些物体，但也会改变主体、降低与切换前主体的面部相似度。据此提出 Molt Forcing（免训练）：从冷启动的目标场景重建场景历史，同时有选择地保留来自原缓存的主体 token。16 个场景族上，Molt Forcing 去除旧场景物体的可靠度至少与 Echo-Forcing 硬切换相当，同时主体外观更接近切换前。

对广域的启示：这是 Boxoffice "stale cache" 动态在真实系统里的一个实例——缓存里的状态带着"它当初是什么角色"的方向性信息，角色翻转后就会造成污染。跨域复用时，"这份 KV 是从哪种上下文里缓存的"必须作为元数据一起传，否则接收端无法判断它是否 stale。作者的做法（重建场景历史 + 只保留主体 token）等价于"部分失效 + 部分复用"，这正是跨域缓存该有的细粒度失效语义。

3. Thinking in Streams: Proactive Spatial Reasoning with Vision-Language Models

  • 链接：https://arxiv.org/abs/2611.25865
  • 时间：2026-11-19
  • 方向：KV 作为空间记忆 · 流式更新 · 主动响应

摘要：在流式视频里识别某个空间条件何时成立，需要在视角不断变化中维护并更新空间知识。论文以"主动空间推理"研究该能力：模型预先收到一个 query，并在流展开过程中判断是否以及何时响应。作者提出 ProSpace-Bench（覆盖物体、相机、场景推理的九类任务）与 ProSpace-Train（监督训练）。为支撑空间决策，ProSpace-VLM 把从来到的帧中因果估计出的显式几何编码注入 VLM 的中间层，把现有 KV cache 当作空间记忆，并用空间 token 选择实现高效流式处理。实验显示 VLM 与人类存在显著差距，而 ProSpace-VLM 在及时响应与正确弃答上优于微调基线；分析还考察了它在视角变化下如何表示此前观察到的空间信息。

对广域的启示："KV cache 当记忆"是一种明确的用法：不需要把历史帧重新编码，只需要维护 KV 并往里写新的几何信息。跨域版本的含义是——记忆只增量更新（每帧只写一小段），而不是每轮重传整段历史。

二、流式多模态缓存（2 篇）

4. AURA: AUdio-dRiven streaming Avatar

  • 链接：https://arxiv.org/abs/2611.26540
  • 时间：2026-11-19
  • 方向：滚动 KV 缓存 · 流式头像 · 两阶段蒸馏

摘要：当前音频驱动视频扩散模型能合成逼真的说话头，但通常要在多秒视频块上做几十步去噪，因而不适合语音助手、虚拟形象这类要求低延迟与在线因果生成的流式应用。AURA 逐块生成视频并使用滚动 KV cache，只需当前块的音频就能开始生成，而不像双向模型那样需要多秒音频前瞻。它有两个规模：AURA 1.3B 在单 GPU 上实时输出 576p（16Hz 播放率下 20.7 fps），适合交互式头像；AURA 5B 以 9.7 fps 流式输出 720p。两阶段蒸馏先把因果学生与教师对齐（用更少扩散步与块级滑窗因果注意力掩码匹配教师轨迹），再用带反向模拟的 Distribution Matching Distillation（DMD）消除剩余质量差距。标准说话头基准上，AURA 1.3B 比自己的双向教师快 23×，在更低分辨率下质量接近 TalkVerse；AURA 5B 在 720p 匹配 TalkVerse 教师且快 17×。作者还开源了两个模型权重、3 万段合成视频数据集与预计算教师轨迹。

对广域的启示："滚动缓存 + 只依赖当前块输入" 是流式跨域的最优形态——不需要前瞻窗口，因此不需要跨节点预取未来数据。跨域流式生成的带宽可以按"块"粒度稳定摊开，而不是突发大块。

5. LiveVAE: Causal Window Attention Makes Efficient Streaming Video VAE

  • 链接：https://arxiv.org/abs/2611.34912
  • 时间：2026-11-25
  • 方向：因果窗口注意力 · 流式 VAE · 编码也高效

摘要：视频扩散模型越来越快、越来越可流式，但 视频 VAE 仍是交互式生成与编辑流水线中的主要延迟瓶颈。现有 VAE 及其加速方法主要依赖重卷积或全帧注意力，且多数只关注解码，把编码留给了流式条件生成与编辑这类高成本场景。论文先问：视频 VAE 的编码与解码是否真的需要全局时空建模？通过分析预训练视频 VAE 的有效感受野，他们发现编码与解码一个 patch 几乎只依赖其空间与时间邻居。据此用因果窗口注意力替代全局建模，在编码与解码两侧都取得高效流式能力。

对广域的启示：感受野分析是"该缓存多少"的根——如果局部性足够，跨域就只需要最近邻窗口的状态，历史可以丢。这条与 KV 压缩里的"局部窗口足够"假设同源，但这里给了预训练模型上的实测依据。

三、存储与调度（2 篇）

6. Synapse: An HBM-Coordinated HBF Near-Memory Computing Architecture for Pipelined Agentic AI Execution

  • 链接：https://arxiv.org/abs/2611.29901
  • 时间：2026-11-23
  • 方向：HBM-HBF · 近存计算 · 多 agent

摘要：多 agent 视频推理时，模型权重与每个 agent 的 KV cache 会超出高带宽内存（HBM）容量。高带宽闪存（HBF）能加容量，但 agent 仍要等 GPU 执行。Synapse 是 HBM 协调的近存计算架构，把 HBF 上的注意力与专家执行同 GPU 计算跨 agent 重叠，并减少派发延迟与不必要的刷新。三个模型上，Synapse 相对"GPU 执行 + 被动 HBF"实现 48.92–66.60% 更低的端到端延迟、最高 2.98× 吞吐、最高 64.48% 更低的每输出 token 建模能耗；磨损模拟预计在同等负载率下 HBF 寿命比块级刷新长 46%。

对广域的启示："让远端能算"比"把远端数据搬回来"更省——Synapse 把注意力和专家计算放在存 KV 的那一层执行，只把结果送回。跨域架构里，这条对应"远端 prefill/远端注意力"，能显著降低链路需求。

7. RankCast: Phase-Aware Rank Balancing in MoE Serving

  • 链接：https://arxiv.org/abs/2611.33542
  • 时间：2026-11-24
  • 方向：PD 分离 · MoE 负载均衡 · 前后缀阶段差异

摘要：现代 LLM 推理越来越多采用分离式架构（把 prefill 与 decode 阶段分开），同时大 MoE 模型服务广泛采用专家并行（EP）。但负载不均衡仍拖慢 MoE 推理，因为每层都要等最忙的 EP rank。延迟主因在 prefill 与 decode 之间不同：prefill 是计算受限的，其 MoE 层延迟由最忙 rank 的最大 token 数决定；而在中等 batch 下 decode 是内存受限的，延迟由跨 rank 的最大活跃专家数主导。RankCast 据此做阶段感知的均衡（针对两个阶段的瓶颈分别调度/重排）。

对广域的启示：分离式部署必须先分清每个阶段的瓶颈类型——计算受限阶段看 token 数、内存受限阶段看活跃专家数。跨域分离会把"阶段瓶颈"与"链路瓶颈"叠加，若不做阶段感知，跨域调度很容易优化错目标。

四、隐私、验证与语音（3 篇）

8. Ask in the Crowd: Differentially Private LLM Inference via Dummy-Augmented Shuffling

  • 链接：https://arxiv.org/abs/2611.25669
  • 时间：2026-11-19
  • 方向：差分隐私 · 假查询混洗 · LLMaaS

摘要：LLM 越来越多以 LLM-as-a-Service 形式部署，用户查询被发往远端推理，带来敏感输入暴露的严重隐私问题。差分隐私推理通过在输入嵌入中注入噪声来缓解，但现有方法难以平衡隐私与效用：更强的保护常导致 LLM 推理准确率大幅下降。论文提出 DP-SPD：通过把真实查询藏在客户端生成的假查询中来保护它，所有查询在发送前被随机混洗，从而在不明显牺牲可用性的前提下提供差分隐私保证。

对广域的启示："混洗 + 假样本"是一种低成本的跨域隐私手段——它不要求修改模型，只需在客户端侧做批处理与打乱。跨域调用第三方推理时，这类机制比"加密整条链路"更轻，但要注意它保护的是统计意义上的输入分布，不是单条查询的机密性。

9. FlashProve-Next: Verifiable Inference for Production LLM APIs

  • 链接：https://arxiv.org/abs/2611.33741
  • 时间：2026-11-25
  • 方向：可验证推理 · 零知识掩码 · 生产特性兼容

摘要：闭源权重 LLM API 的客户无法验证服务方是否真的运行了宣称的模型、精度、隐藏 prompt 与推理预算。现有方案要么信任硬件或第三方，要么以高成本重证整数替代模型的每一层、并与原生浮点服务脱节。FlashProve-Next 为单个 LLM API 响应生成可验证、零知识掩码的证明，且不修改原生服务（bf16/fp8/mxfp4、随机采样、FlashAttention、CUDA graph、批处理、前缀缓存），也不泄露权重、隐藏 prompt、隐藏推理或激活（密集 profile 固定粗粒度几何；跨架构隐藏留待后续）。

对广域的启示：前缀缓存是"可验证服务"必须兼容的生产特性——这反过来提示：跨域缓存共享若涉及多信任域，缓存命中本身也需要可信证明（否则无法证明"我确实复用了你说的那段"）。这条线目前几乎没人做，是个空白。

10. TigerTTS: Draft-Guided Multi-Frame Parallel Speech-Token Language Model for Fast and Robust Text-to-Speech

  • 链接：https://arxiv.org/abs/2611.34241
  • 时间：2026-11-25
  • 方向：草稿引导 · 多帧并行 · 生产级 TTS

摘要：自回归语音 token 语言模型能实现高质量 TTS，但存在随序列长度增长的延迟、缺少显式对齐导致的漏词或重复、以及离散码本带来的保真度上限。TigerTTS 是生产级 LLM TTS 系统，围绕一个轻量非自回归（NAR）模型构建：在显式对齐下，NAR 模型为整段话语起草 token，再由紧凑的自回归 LLM 逐帧精化；草稿与 LLM 目标逐帧对齐并注入输入端，保证训练-推理一致。借助该精度，LLM 每步预测跨 3 帧 4 组的 12 个 token。

对广域的启示："先并行起草、再逐帧精化" 与投机解码同构，但把草稿从"额外模型"换成了同一系统的 NAR 头。跨域流式语音的启示是：把串行依赖压到最小（每步 12 token），能直接降低往返次数——这对 RTT 敏感的场景比压缩字节更有效。

今日观察

  1. "陈旧缓存"从理论动态变成了实机现象：The Old Scene 证明 KV flush + sink 重算仍清不掉旧场景，因为历史同时承载主体一致性。跨域复用必须把"缓存时的上下文角色"作为元数据一起传。
  2. 状态接口能把传输量与长度解耦：Markovian 结构缓存把历史 KV 换成常数大小状态传输——前提是任务真的马尔可夫。
  3. 局部性有实测依据：LiveVAE 用感受野分析证明 VAE 编解码几乎只依赖时空邻居，为"只缓存窗口"提供了模型侧证据。
