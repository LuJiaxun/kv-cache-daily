一、重点方向：混合/线性注意力与 KV 共享·检索（3 篇）

1. HySparse2: Hybrid Sparse Attention with Two-Level KV Sharing

  • 链接：https://arxiv.org/abs/2609.26368
  • 时间：2026-09-22
  • 方向：混合稀疏注意力 · 两级 KV 共享 · 跨层构造

摘要：长程与多轮 agent 通常只生成很短的动作，却要处理来自工具与环境的长观测，因此同时需要高效 prefill、紧凑 KV 存储与准确的长上下文检索。HySparse2 是带两级 KV 共享的混合稀疏注意力架构。外层 KV Bridging 采用 YOCO 式的 self-decoder + cross-decoder 结构，但只桥接全注意力层：self-decoder 用混合滑窗注意力（SWA），cross-decoder 用混合稀疏注意力；cross-decoder 中全注意力层的 KV cache 由 self-decoder 中全注意力层的隐状态生成。内层保留 HySparse 的核心 KV Reuse 设计并做两点改进：把块级稀疏换成 token 级稀疏（更细的长上下文检索），并去掉稀疏层里单独的 SWA 分支、改为把最近 token 的滑窗强制并入稀疏选择。两级共享使 cross-decoder 的全部 KV cache 都能由 self-decoder 隐状态构造，于是prefill 可以在 self-decoder 之后提前退出、跳过全部 cross-decoder 层。在 80B-A3B MoE 上，HySparse2 在长上下文检索与多轮 agent 任务上优于 HySparse 与 Hybrid SWA，同时大幅降低 prefill 计算与 KV 存储。

对广域的启示："KV 由隐状态现场构造"就是最强的传输优化——如果 cross-decoder 的 KV 不需要单独存/传，跨节点只需搬 self-decoder 的隐状态。这与之前收录的 MemOnce（存小解大）、CarrierKV（剥离位置载波）是同一族思路：减少需要过网的独立状态数量，而不是压缩每一份。

2. Integral DeltaNet: Improved Linear Attention with Adaptive Memory Integration

  • 链接：https://arxiv.org/abs/2611.32063
  • 时间：2026-11-24
  • 方向：线性注意力 · 双互补状态 · 多时间尺度

摘要：线性注意力用线性形式替代 softmax 注意力，从而实现线性时间计算与固定大小的循环状态（而非增长的 KV cache）。但这种把历史压进固定状态的做法会造成记忆碰撞，伤害长上下文理解。DeltaNet 用 delta-rule 更新缓解碰撞，Gated DeltaNet 又加了门控，但这些机制也可能丢弃对未来预测仍有用的信息。Integral DeltaNet 因此维护两个互补的循环状态：快速更新的 delta 状态（捕捉当前 key-value 关联）与一个积分状态（保留 delta 状态的加权历史）；读出时自适应地组合二者，从而跨时间尺度取用信息。论文还推导了 chunkwise 并行形式以支持高效训练。340M 与 1.3B 模型分别在 15B 与 100B FineWeb-Edu token 上从零训练，在语言建模、常识推理、真实与合成检索、长上下文理解和长度外推上均优于强循环基线，并对比了训练吞吐、激活内存与解码延迟/内存。

对广域的启示：状态设计决定了"要不要传历史"——双状态让模型能在不同时间尺度上调取信息，等价于把"长历史"编码进一个固定的、可整体搬运的小状态。对跨域而言，这种架构天然适配"传状态不传 KV"。

3. DraftKV: Protecting Persistent Worlds through Hierarchical Streaming Retrieval

  • 链接：https://arxiv.org/abs/2611.31944
  • 时间：2026-11-24
  • 方向：历史 KV 非前缀检索 · 流式注意力 · CPU 卸载

摘要：交互式视频世界模型支持动作与相机控制的探索，但在重访已探索位置时难以保持空间几何与外观一致。历史 KV cache 能帮自回归视频扩散模型维持长期一致性，但随着历史增长，其检索与注意力计算带来可观的延迟。DraftKV 是免训练框架：基于几何接地与查询条件相关性检索历史 KV，并结合 CPU 卸载与分块流式注意力降低显存与延迟。理论上证明：draft 相关性精确复现了全分辨率块相关性的均值分支，偏差被限制在 β 加权的 max 分支；并用实测 Top-K 选择重合度给出检索效用损失的界。论文还证明 draft 相关性无法区分池化描述子相近的块（与相机位姿无关），因此在精排之前需要几何接地。其流式 CG-Attention 通过分块流式把 CPU→GPU 的 KV 传输与注意力计算重叠，隐藏传输延迟同时保持显存有界。多模型族实验上，DraftKV 端到端加速 3.27×、峰值显存降 42.2%，并在单张 H100 上用 SolarWM-33B 实现可交互的高质量世界生成。

对广域的启示："按需检索历史 KV"就是非前缀复用的实例——重访时并不需要前缀连续性，只需要找到"当时那段状态"。它的流式重叠技巧（传输与计算重叠、显存有界）是跨域取历史的直接可复用做法；而"几何接地先于语义精排"的教训也适用于跨域缓存索引：先按结构定位，再按语义打分。

二、存储分层与放置（3 篇）

4. LoomKV: Lossless KV Cache Compression from GPU Memory to SSD for LLM Serving

  • 链接：https://arxiv.org/abs/2611.32954
  • 时间：2026-11-24
  • 方向：无损压缩 · GPU→DRAM→SSD · 引擎集成

摘要：服务引擎把 KV 从 GPU 显存卸载到主机 DRAM 与 SSD，以支持多轮与 agent 请求的前缀复用；容量于是在两层受限：外部层级决定驱逐前能复用多少前缀，GPU KV 池限制并发长请求，而有损压缩会改变 KV 值与输出。LoomKV 在不改引擎的前提下把无损 KV 压缩同时用于外部层级（tier 模式）与 GPU 池（pool 模式）。它用标定的 per-head 两级 3-bit 码编码 BF16 的高字节（符号位 + 高 7 位指数）：九个模型上把 BF16 KV 存到原始大小的 0.71，FP8 KV 存到 0.85–0.87。tier 模式下 TileStream 写入精确长度记录、把长度回读移出加载路径，使层级存储、驱逐与预取逻辑不变，并把取回的记录直接解压进分散的 GPU 页；pool 模式下 FragPack 把变长记录打包进更小的共享预算 GPU 页，由融合解码-注意力 kernel 原地读取，速度超过 BF16 上的 FlashAttention-3。基于 LMCache 与 vLLM 构建，LoomKV 让压缩层级在 AgentX 上等效于 1.4× 更大的原始层级：跨 LMCache 的 LRU 悬崖，tier 模式给出原始 2.7–3.6× 的 goodput 与 1.9–3.1× 更低的平均 TTFT，在其他替换策略下悬崖位置同样平移，并通过 SSD→DRAM 提升把重复前缀 TTFT 降低最多 1.7×；当层级装得下工作集时，pool 模式能多放 1.31–1.34× 的 GPU token。双受限的 AI IDE trace 上，两种模式分别把 goodput 提升 1.24× 与 1.59×；容量足够时压缩的吞吐代价最多 2.2%，且 tier 模式与原始层级逐位相同、pool 模式精度与 FA-3 一致。

对广域的启示：这是跨域传输最直接可用的一篇：无损 → 跨域压缩不会改变结果（不像 FP8 KV 会翻转 3.36% 判分）；0.71 的存储比 → 跨网字节直接降 29%；"把记录直接解压进分散 GPU 页"意味着接收端可以边解压边就位，不需要中间缓冲。跨域缓存池若走无损压缩，可以同时拿到带宽与正确性两个好处。

5. Cheap Memory Costs Future Compute: Co-Designing Persistent KV and GPU Execution for Efficient Streaming Video Diffusion

  • 链接：https://arxiv.org/abs/2611.31892
  • 时间：2026-11-24
  • 方向：持久 KV 重建 · 陈旧缓存代价 · 流式视频

摘要：块因果视频扩散逐块生成长视频，并以持久 KV cache 为条件。每块去噪完后，需要一次额外的无噪（t=0）前向把它的干净 KV 写入缓存；当蒸馏与投机 early exit 让去噪变便宜后，这次干净 KV 更新反而成为运行时主项。复用陈旧 KV 能缩短更新，但陈旧记忆会污染后续块的 conditioning 并抬高它们的去噪步数——省下的计算会从下游重新出现。论文提出 SAMR（Step-Aware Memory Reconstruction）：对冻结的因果视频 DiT，只刷新部分缓存、其余不经过 DiT 前向重建。关键观察是：去掉 rotary 位置相位后，运动对齐的历史 KV 与 token 在其退出步持有的在飞 KV 是 clean KV 的互补估计。SAMR 在 Pre-RoPE 空间用离线标定的 per-head 仿射映射去偏在飞 KV，融合两个估计，并只对注意力读出误差代理标记的 token 做真正的 t=0 刷新，全部由 tile 对齐、无同步的 Triton kernel 执行。48 秒 LongLive-1.3B 视频上，相对稠密 KV 更新把 DiT 延迟降 20.9%、主 FLOPs 降 30.7%，并降低下游去噪步数、末四分之一 PSNR 比 token 复用高 1.61 dB（held-out VidProM-16 上 1.14 dB）；对 Self-Forcing-DMD-1.3B 零样本迁移可把复用导致的步数膨胀从 2.47 降到 2.30 步/token。

对广域的启示："省带宽的代价可能在别处付"——陈旧 KV 省了更新成本，却抬高下游计算。跨域复用陈旧缓存（比如跨 region 同步延迟导致的旧版本）必须把这种下游惩罚计入收益模型；SAMR 的"部分真刷新 + 其余重建"正是折中方案。

6. Norn: Context-Length-Aware Optimization of Weight and KV Cache Placement for Offloaded LLM Inference

  • 链接：https://arxiv.org/abs/2611.32295
  • 时间：2026-11-24
  • 方向：上下文感知卸载 · 子层放置 · 计划切换

摘要：把模型权重与 KV cache 卸载到主机内存，能让大模型在单张受限 GPU 上运行。但随着解码推进 KV 增长，显存需求、KV 传输成本与注意力计算成本都在变；现有卸载方法一般用静态的计算分配与权重/KV 放置，无法适应这些变化，性能因此退化。Norn 是上下文长度感知的卸载推理方法：基于离线剖析，在子层粒度上协同优化计算分配与放置，预计算多套执行计划及其切换点；解码时随上下文增长切换计划，在不知道输出长度的前提下重叠计算与数据传输。对 prefill，Norn 用 operator-major 的 chunked prefill 避免重复权重传输，并自动选择 chunk 大小。Qwen3-14B 与 Qwen3-32B 在两套单 GPU 系统上，端到端延迟相对 Pipelined Sharding 最高 16.8×，相对"已知输入输出长度"的 oracle 变体也有 4.2×。

对广域的启示："放置要随上下文长度动态变" 对跨域同样成立：随着上下文增长，最优的"本地/远端"分工会发生迁移。Norn 的"预计算多套计划 + 按上下文切换"是廉价可行的实现——跨域方案可以预先算好几种 region 分工，运行时按上下文长度切换。

三、边缘与 Serverless（2 篇）

7. Scalable Placement for Disaggregated LLM Serving on Heterogeneous Edge Fleets

  • 链接：https://arxiv.org/abs/2611.32881
  • 时间：2026-11-24
  • 方向：边缘异构集群 · PD 分离放置 · 组合优化

摘要：在边缘服务 LLM 对隐私敏感场景很有价值，但边缘环境算力受限且设备高度异构，突发负载下拥塞与排队会显著拉高延迟。把模型复制成多个流水线实例能扩容、降拥塞，但"设备如何分组为副本、副本如何分配 prefill/decode 角色、模型层如何在异构设备上切分"共同构成一个很大的组合优化问题。论文提出 Spade，面向异构边缘集群、支持流水线复制的 PD 分离放置规划器：用支配关系剪枝丢弃劣质副本候选并递归消除包含它们的更大候选，大幅缩小搜索空间；再用注水式层切分与带界多维背包在拥塞感知目标下优化放置。30 台设备、五个硬件类别的合成集群上，Spade 441ms 找到最优放置，而遗传搜索基线需要约两小时且拥塞目标差 19.7%；十种设备类型的集群上，剪枝消除 99.6% 的候选而存活集合与穷举完全一致。

对广域的启示：跨域部署本质上就是"异构设备 + 分离 + 复制"的放置问题——Spade 的形式化（支配剪枝 + 注水层切分 + 拥塞目标）可以直接移植：把跨域链路带宽/时延作为额外的设备约束，就能规划"哪些 region 做 prefill、哪些做 decode"。

8. ModelLess: A Serverless System for Multi-Tier LLM Inference on Shared GPUs

  • 链接：https://arxiv.org/abs/2611.32634
  • 时间：2026-11-24
  • 方向：Serverless · 多优先级 · 驱逐语义

摘要：LLM 推理平台按产品分别预留 GPU，导致一个服务在突发间隙闲置、而其他工作排队。ModelLess 是 serverless 系统：用户声明模型服务，平台拥有实例；空闲服务缩到零——实例带着权重睡进主机内存（GLM-5.2 TP8 上释放约 1s、唤醒约 4s，而冷启动超过 4 分钟），计费按服务占用 GPU 的时间。睡着的实例释放出的 GPU 借给低优先级层。集群管理器通常把驱逐当全有或全无，但 LLM 实例的驱逐代价取决于其权重、执行状态、KV cache 与在飞请求哪些能存活。ModelLess 因此给每一层（online/job/flex）规定驱逐语义（声明被抢占时允许丢什么），并运行抢占协议：释放内存前先关闭准入、中止请求前先持久化重新入队、失败即关闭。单节点实验显示：暂停（pause/resume）相对"中止-重排"每 GPU 样本多产 22% 借用者 token，而在线延迟中位数相同；1100 张 H20 一周 trace 回放表明，在粗延迟目标下约 38% 的 GPU 时间（等效 417 张卡）可被借出——但这是理想上界，只有恢复能在秒级完成时成立，240s 冷启动下即便按服务设阈值也剩不到 8%。

对广域的启示："驱逐代价取决于哪些 KV 能活下来" 是跨域池化必须显式化的语义——跨域驱逐意味着 KV 要么重算要么跨网重取，代价比本地驱逐更高。ModelLess 的"分层驱逐语义 + 先关准入再释放"是跨域资源池可以直接借用的协议设计。

四、内核与 Agent 压缩（2 篇）

9. Fast 4-bit KV-Cache Decoding on Hopper GPUs: Why Existing Kernels Are Slow and How to Fix Them

  • 链接：https://arxiv.org/abs/2611.30027
  • 时间：2026-11-23
  • 方向：4-bit 解码内核 · 指令预算 · 精度配方

摘要：4-bit KV cache 读取的字节约为 FP8 的一半，但 Hopper 没有 FP4 硬件、且每字节带宽对应的指令发射能力很小，所以 4-bit 必须用软件解码。H200 上 vLLM 的 NVFP4 KV 路径（FlashInfer 的 decode）只达到 10–20% 的显存带宽，比 FP8 最多慢 1.7×。NVBit 指令计数显示两个原因：vLLM 的 4-bit 路径背后的 kernel（FlashInfer NVFP4、Triton UltraQuant）每字节执行 2–6 倍的 Hopper 发射预算，且把加载、解码与矩阵乘串行化。论文的 Hopper 原生解码 kernel 用 TMA 生产者 warp + 两个计算 warpgroup 重叠，在写入时就把布局排好使解码值从寄存器直喂张量核，并交换矩阵操作数让小 query 组无需 padding。H200 上 batch 32–128 达到 67–75% 峰值带宽，全部 11 个形状上比 XQA 与 FlashAttention-4 提出的原生 FP8 中较快者快 1.12–1.49×。集成进 vLLM 并配精度配方（K 均值移除 + 旋转、4 个 BF16 sink token、第 0 层 BF16）后，Llama-3.1-8B 上 batch≥8 时每步解码比 vLLM 的 FP8 路径快 1.12–1.64×，能多容纳 1.63× 的 token；单张 H200 上 99% 请求满足延迟目标的最高速率是 FP8 的 1.23–1.32×（Llama-3.1-8B）与 1.67–2.20×（Qwen2.5-72B）。五个 7B–32B 模型上重复运行与 BF16 KV 无显著精度差异；对 FP8 KV 会崩的 Qwen2 推理变体，第 0 层的 key 均值几乎就是 key 投影偏置，保留该层 FP8/BF16 即可恢复。

对广域的启示："低位宽不等于省"——如果解码 kernel 吃掉了指令预算，4-bit 可能比 FP8 还慢。跨域方案在选位宽时，必须先确认接收端的解码实现能否跟上；本期的 LoomKV（无损、逐位相同）与这篇（4-bit 需专门 kernel）形成对照：压缩比与可执行性是两件事。

10. DMC-5: Dual-Model Collaboration with Cache-aware Context Compression for Long-horizon Agents

  • 链接：https://arxiv.org/abs/2611.30412
  • 时间：2026-11-23
  • 方向：双模型协作 · 缓存感知压缩 · 只追加视图

摘要：长程 agent 反复把不断增长的交互轨迹喂给专用 agent 模型。前缀缓存能复用重复历史的计算，但既不能阻止上下文增长，也不能移除与当前决策无关的信息；当专用 agent 拿不到通用模型那种缓存输入折扣时，这个代价尤其高，于是轨迹压缩成为自然选择。但已有压缩方法有风险：选择性上下文会丢全局信息、递归改写摘要导致语义漂移、反复重压全历史又把增长的成本转给压缩器。DMC-5 是非对称框架：全历史整合交给通用压缩模型，动作生成交给专用 agent 模型。它把原始轨迹保留为只追加的规范视图（Append-only Canonical View），保住全局可访问性，同时让压缩器复用稳定的历史前缀而不是递归改写或重算；agent 只在一个紧凑的决策视图上工作（近期原始交互），减少重复输入又保住下一步动作所需信息。它还引入 YAMATO（面向工具操作的完整性感知记忆抽象）在有损压缩中保住执行关键信息。AppWorld、OfficeBench 与 8 目标 QA 上，DMC-5 把 agent 模型输入减 38.5%–57.0%、端到端成本降 14.5%–28.0%，压缩器缓存命中率 78.0%–85.0%，同时任务表现比未压缩基线提升 1.0–5.8%。

对广域的启示："只追加的规范视图"是跨域 agent 的关键设计——它同时满足了"可复用稳定前缀"与"可回查全局"两个需求。跨域场景里，把规范历史放在源头（只追加、前缀稳定），把决策视图放到 agent 侧（小、可传），正好匹配广域链路的成本结构。

今日观察

  1. 混合架构的"共享"从缓存层上升到架构层：HySparse2 让 cross-decoder 的 KV 全部由 self-decoder 隐状态构造，prefill 可以提前退出——减少需要存/传的独立状态数量，比压缩每一份更彻底。
  2. 无损压缩出现了生产级方案：LoomKV 在 BF16 高字节上做两级 3-bit 码，0.71 倍存储、位精确、goodput 2.7–3.6×。这解决了"压缩会不会改结果"的顾虑。
  3. 陈旧缓存的代价会在下游出现：SAMR 证明复用旧 KV 省的更新成本会变成后续更多的去噪步数。跨域同步延迟造成的"旧版本 KV"同样要按此折算。
  4. 位宽选择要看接收端能不能跑：4-bit 在 Hopper 上因指令预算不足反而比 FP8 慢 1.7×；压缩比高不等于端到端更优。
