一、重点方向：混合 / 循环架构与跨版本迁移（3 篇）

1. PackLoop: Row-Packed Self-Speculative Decoding for Looped Language Models under Concurrency

  • 链接：https://arxiv.org/abs/2611.30205
  • 时间：2026-11-23
  • 方向：循环 LM · 并发行程 · 精确自投机

摘要：循环语言模型每 token 把同一组权重重复用 T 次，用参数换测试时深度，代价是自回归解码要付 T 次串行 pass。自投机解码对单请求能拿回 2–10×，但请求共享 GPU 后增益消失，业界做法是"负载越高越少投机"。论文指出：负载下失效的是投机工作的布局，而不是投机本身。并发解码时成本的单位是行（一个请求在一个循环上前进，读该循环的 KV cache 一次），同一行里多加位置几乎免费。wavefront 这类流水调度把每个投机位置放到不同循环、也就是各自成行，于是每 token 仍要被读 T 次。PackLoop 的原则是"只在反正要读的行里投机"：深循环累积位置成块在一行内前进、context-copy 提议并入第一循环本就读取的行，并用库存论里的经济订货量（EOQ）闭式准入规则决定累积多久（成本模型每引擎标定一次）。PackLoop 是精确的：FP32 下输出与自回归逐 token 相同（采样与 early exit 下亦然）。三块 GPU、四个 Ouro 模型、六个基准、最长 32K 上下文的 164 个负载点上，单一配置在 161 个点上快于"每点最优的现有调度"（中位 1.25×、最高 1.76×），且从不变慢；领先幅度随并发与上下文长度增长。

对广域的启示："成本单位是行，不是位置" 这个视角对跨域同样成立——一次远端读取的成本由"读了几份缓存"决定，而不是"算了几步"。跨域调度应当把同一份 KV 上的多个投机位置打包在同一次传输里，这样"多投机"几乎不增加带宽。

2. One Million Tokens in 20GB: Calibration-Free 2-Bit SRFT KV-Cache Compression for Looped MoE Inference on Apple Silicon

  • 链接：https://arxiv.org/abs/2611.29092
  • 时间：2026-11-21
  • 方向：循环 MoE · 端侧 2-bit · SRFT

摘要：统一内存边缘机器上的长上下文推理受 KV 容量与带宽支配。在 32GB Apple M6 Mac mini（26.8GB Metal 工作集、150GB/s DRAM）上，26.4B 的循环 MoE 模型 Inkling-2-Mini（48 次逻辑访问、1M 原生上下文）在原生 oMLX 里 64K token 就耗尽内存；即便把 40 个滑窗访问修成有界 ring buffer，也只能撑到 512K。论文指出，现代混合 NoPE 架构的三个结构性质——有界滑窗、1,024-token 带状相对偏置且尾部恒为零、unit-RMS value 归一化——配合正交 SRFT 变换，可实现免校准、免 scale 的 2.000-bit Value + 2.125-bit Key Lloyd-Max 压缩（2.0625 有效 bit/坐标，比 bf16 小 7.76×），作用于 8 个全局访问的远前缀 [0, N-1024)，与精确 bf16 局部窗口和学习到的 sink 通过 online log-sum-exp 合并。自研 GQA 打包 Metal decode kernel（256 项 half4 LUT + Block-8 惰性 exp2 重缩放）达 73.4 GB/s：256K 下 17.09 tok/s（比 bf16 快 3.36×）、512K 13.81 tok/s、1,048,576 token 时 9.52 tok/s，峰值内存 19.49 GiB（其中 KV 4.37 GiB）。4×4096 WikiText-2 窗口上 3.06-bit SRFT 无损（ΔPPL −0.007）、2.56-bit 加 +0.024、2.06-bit 加 +0.130，同时在 8K/16K/32K 上保持 100%（3/3）的 7 位 passkey 精确检索。

对广域的启示：这是"极致压缩让不可能变可能"的样板：同一台机器上 64K 直接 OOM，2-bit 后能跑 1M。对跨域的含义是——不要把"KV 太大传不动"当结论，先看能压到多少；7.76× 的压缩比意味着 100GB 的跨域状态只需 13GB。

3. LiveLoRA: Exact KV Cache Migration Across LoRA Updates for LLM Agents

  • 链接：https://arxiv.org/abs/2611.31105
  • 时间：2026-11-23
  • 方向：跨版本迁移 · 精确等价 · Agent 会话

摘要：更新 LLM adapter 不应该要求重放所有活跃会话的完整交互历史。然而复用旧版本算出的 KV 条目会混用模型版本，而全历史 re-prefill 会随历史与会话规模增长越来越贵。LiveLoRA 是模型-运行时协同设计，实现精确的 final-block KV 迁移：冻结的低层 decoder block 与固定的 K/V adapter 下投影让每个 token 的 base 投影与低秩坐标跨 adapter 版本保持不变；运行时重建候选 K/V、把最新 token 过一遍 final block、并把 adapter、cache 与 next-token logits 一起提交。论文证明其在精确算术下与全历史 re-prefill 的续写等价。Qwen2.5-3B-Instruct 上，32 个活跃会话、每个 8K token 时，相对全历史 re-prefill 的中位配对发布加速 5 次运行平均 68.98×；服务基准显示相对原生缓存解码约 4.8% 的解码开销；相比"保留边界重放"，紧凑保留在 8K 下把额外会话存储减少 3.42×，而发布+解码成本相近。

对广域的启示：模型版本更新不必作废跨域缓存——只要把变化限制在 final block 并保持 base 投影/低秩坐标不变，就能在"版本混合"下做到精确等价。对跨域共享池，这意味着 adapter 更新可以只让最后一层失效，而不是整池 KV 作废。

二、压缩与驱逐（3 篇）

4. Gossamer: A Utility-Driven Architecture for Constant-Budget KV Cache Compression in Reasoning LLMs

  • 链接：https://arxiv.org/abs/2611.29497
  • 时间：2026-11-22
  • 方向：恒定预算 · 效用驱动动作 · 免费算力

摘要：推理任务把上下文推到几十万 token，KV 成为内存与带宽的主导项。现有压缩（量化、驱逐）多停留在算法层，常引入额外 pass 与计算开销。Gossamer 是打通算法-系统-硬件的 KV 压缩架构：用统一的效用驱动动作框架在恒定 KV 预算下动态选择量化、合并或驱逐；通过跨域协同设计，把余弦相似度估计直接融进注意力计算，利用空闲算力周期做相似度评估而不增加延迟与带宽——称为 Free-Lunch Utilization。这带来实时、细粒度、近恒定内存的 KV 管理。紧内存约束下，Gossamer 保持与大模型未压缩推理相当的推理质量，端到端吞吐相对未压缩基线最高 16.7×、相对量化的 Oaken 与 Ecco 分别 5.5× 与 4.9×、相对驱逐的 R-KV 1.8×。

对广域的启示："用空闲算力换压缩判断" 在跨域同样成立：传输等待、排队间隙都可以用来算"哪些 KV 重要"。把判断成本藏进空闲周期，压缩就不再是纯收益的减法，而是可以更激进。

5. RefineKV: Query-Adaptive KV Cache Compression via Attention-Error Bounds

  • 链接：https://arxiv.org/abs/2611.28171
  • 时间：2026-11-20
  • 方向：查询自适应 · 误差上界 · 聚类代表

摘要：反复访问完整 KV 是长上下文解码的主要瓶颈。论文发现：每个查询只需小部分 KV 就能准确近似全注意力，但这些子集的并集几乎覆盖整个缓存——这正是"按查询自适应访问"的动机。直接做法是把 KV 切成簇，对误差可忽略的簇用紧凑代表、其余展开为原始条目。论文从注意力输出误差的上界推出选择准则，并揭示支配误差的两个互补因素：重要度（簇的影响力）与失真（簇能被多忠实地表示）。据此提出 RefineKV，一个解码期查询自适应的 KV 压缩方法。两个模型三个基准上，RefineKV 保持接近全注意力的质量，注意力阶段最高 7.6× 加速、解码 1.66× 加速，建立了新的质量-延迟 Pareto 前沿。

对广域的启示："重要度 × 失真"的双因素准则可以直接搬到跨域缓存分层：高重要度且低失真的簇值得精确传输，低重要度的簇传紧凑代表即可。这比单一"注意力分数"排序更能指导带宽分配。

6. NoHairCache: Calibrate-Once KV Cache Eviction with One Power-Law Exponent

  • 链接：https://arxiv.org/abs/2611.29006
  • 时间：2026-11-21
  • 方向：驱逐统一框架 · 幂律指数 · 一次校准

摘要：KV 驱逐中的衰减指数 α 是模型的内在属性：在单一语料上校准一次就能跨域迁移。基于注意力的累积（H2O）与基于新近度的滑窗（StreamingLLM）常被视为两个无关框架，论文证明它们是同一个幂律族的两个端点：以 $s_i = A_i \cdot (t-i)^{-\alpha}$ 打分（A_i 为累积注意力、α 控制年龄惩罚），H2O 对应 α=0、StreamingLLM 对应 α→∞（后者还硬编码了 attention-sink 补丁）。NoHair 机制给出 α 的可容许范围，实测指数与之吻合：在 WikiText 上校准一次，代表性模型 Qwen2.5-1.5B-Instruct 得 [0.556, 0.822]；五个模型（410M–1.5B）的区间一致，并独立地与困惑度扫描的最优区域匹配。NoHairCache 在 WikiText/PG19/arXiv 三个数据集上取得最低困惑度、无需按数据集调参，优于 H2O 与 StreamingLLM（三个数据集均 p<0.05，预算 512 时比 StreamingLLM 好 0.06–0.10 PPL）。下游四选一 QA 上九个（任务, 预算）格中全部追平或超过 StreamingLLM，NarrativeQA 25% 保留时保住 98.2% 全缓存精度（StreamingLLM 为 91.1%）。

对广域的启示：一个模型只需要一个标量参数就能确定驱逐策略——这对跨域部署极友好：多节点共享同一模型时，α 可以离线标定一次并全局下发，不必每个 region 各自调参。也说明"注意力累积"与"时间衰减"不是对立方案，而是同一谱系。

三、系统、安全与部署（2 篇）

7. HiPerfCC-KVCache: Accelerating Confidential LLM Serving with Hierarchical KV Caching

  • 链接：https://arxiv.org/abs/2611.28702
  • 时间：2026-11-21
  • 方向：机密计算 · 受保护传输 · 分层缓存

摘要：分层 KV 缓存把可复用状态保留到 GPU 显存之外，减少重复 prefill；但在 GPU 机密计算（CC） 下，受保护的传输可能抵消这份收益。论文表明：批量 KV 拷贝会在漫长的 CPU 侧处理期间持有驱动锁，即便线程与流相互独立，也会阻塞其他服务操作。作者在 Hopper 与 Blackwell 上刻画了锁范围、拷贝粒度、分配所有权如何影响前台进度与传输并行度。据此提出 HiPerfCC-KVCache：管理资源生命周期、在有界备份提交之间优先完成就绪 token 回读、并通过辅助上下文的共享 GPU staging 并行化 KV 恢复。在 SGLang 上实现，只使用现有受保护传输接口，不改硬件与驱动。H200 上三个模型三种负载：相比 staged KV-transfer 的 HiCache-Workers 基线，输出 token 吞吐几何平均 1.74×（最高 2.72×），平均 TTFT 降 36%（最高 59%）；在 RTX PRO 6000 Blackwell 上同样有效（几何平均 1.28×、最高 2.20×）。

对广域的启示：加密/受保护传输不是免费的——它会引入锁竞争与串行化，可能抵消缓存复用收益。跨域若走加密链路（TLS/机密计算/可信执行环境），必须把"保护开销"计入复用收益模型，而不是假设加密是零成本的封装。

8. Analytical Modeling and Optimal GPU Provisioning for Disaggregated LLM Inference

  • 链接：https://arxiv.org/abs/2611.28760
  • 时间：2026-11-21
  • 方向：PD 分离 · 容量模型 · GPU 配比

摘要：论文提出 OSplit，一个精确解析方法，把 GPU 的 L1 域高效划分为 prefill 与 decode worker（含经典与先进 GPU 的分片）。它把模型参数纳入考虑，目标是在任意推理模型上产出最大吞吐。OSplit 基于容量模型：输入模型、加载方案（batch size、最大序列长度），对推理服务框架（vLLM）建模并算出每块 GPU 的效率；为此对 H100 与 GB300 建模、对 scale-up 域建模，并纳入 FlashAttention kernel。OSplit 先算出最优的集合通信生成策略，再给容量模型提供输入以得到最优 prefill/decode GPU 划分。在 H100（NVL8）与 GB300（NVL72）上用 vLLM 评估，覆盖 Llama 与 Qwen 等主流模型，吞吐与预测/实测延迟接近"理论上限=实测"。

对广域的启示：PD 分离的配比可以解析求出，而不是靠试。跨机房部署时，若两端 GPU 型号/带宽不同，这个建模框架可直接扩展：把跨域链路的带宽与时延当作额外的"GPU 等效成本"代入，就能算出"远端 prefill / 本地 decode"的最优配比。

四、正确性与测试（2 篇）

9. Exact on Paper: Which LLM Serving Shortcuts Flip Graded Answers

  • 链接：https://arxiv.org/abs/2611.29663
  • 时间：2026-11-22
  • 方向：服务特性正确性 · 判分翻转 · 噪声基线

摘要：团队在确认"基准准确率不变"后就会开启前缀缓存、chunked prefill、投机解码等特性，因为引擎文档称它们"精确"。但准确率是聚合量——一个特性可以保住准确率，却翻转"哪些请求被答对"。论文用 vLLM 服务一个 4B 指令模型，跑九种单特性配置与五份参考配置副本，每次运行都对五个基准的 3,380 个请求判分，并把每个候选与两个地板比较：重启地板（全新进程）与调度地板（同样请求换顺序）。结果：默认 kernel 下所有配置准确率都在 1 个百分点内，而七个"精确"特性翻转了 1.47%（95% CI 1.13–1.85）到 1.78%（1.39–2.20）的判分结果——没有一个超过 1.72% 的调度地板；但 FP8 KV cache 翻转 3.36%（2.80–3.96），与 FP8 权重量级相当。换成 batch invariant kernel 后，七个精确特性（含投机解码）在每个请求上都复现参考文本，而 FP8 KV cache 仍翻转 3.91%（3.28–4.53）。论文还发现"用单一副本对做门禁"会把一个未变化的配置判为失败，因此建议：要么在 batch invariant kernel 下认证（地板为零），要么至少用三份副本测出调度地板。

对广域的启示："精确"的服务特性会让同一请求的判定结果翻转 1.5% 左右，而量化 KV 是 2–4 倍于此。跨域复用若涉及测量/评测（比如做跨域方案对比），必须带调度地板；否则 1–2 个百分点的"提升"可能只是重排噪声。

10. Testing Quantized KV-Cache Maintenance: Encoding Layout and Historical Restoration

  • 链接：https://arxiv.org/abs/2611.30720
  • 时间：2026-11-23
  • 方向：量化缓存维护 · 历史恢复 · 契约测试

摘要：重复行再选原值，即便编码次数相同，仍会保留依赖布局的漂移。论文测量了现有检查在"固定量化 KV 实现"上何时无法建立保持契约：4-bit HQQ 轴零、十六个周期下，相对同形状重编码的中位配对相对 L2 分别增加 7.22 个百分点（Qwen3-1.7B） 与 11.59（SmolLM3-3B）。匹配的编码状态在每个模型 16 个共享问题上覆盖一次与十六次周期；轴一与形状保持对照一致；惰性重排保留初始状态；在某已知输入上，固定更新次数保留了差异，保留组成员则消除了它。前缀视图扩展能通过当前前缀检查，却在六种模型/编解码设置、残余容量 4 与 128 时改变历史与下一 token logits。公开查找能触到该边界，包括四次预先承诺的新 GPU 输入之一；固定 query 交换隔离出条件性的旧历史效应。checkpoint/稠密回滚是精确的。论文也明确报告：任务伤害扩展失败，因此不能据此主张总体失败率或一般性答案退化；原生 MLX-LM fixture 暴露了过期的调用方缓存，同步后可恢复被测试的 in-place 契约。

对广域的启示："能通过前缀检查"不等于"历史没被改"——这对跨域缓存校验是直接警告。跨域传输/存储的量化 KV 若经过多次重编码或视图变换，必须在历史恢复这一维上单独测试（checkpoint/稠密回滚是精确的，可作基准），而不能只看当前前缀的输出。

今日观察

  1. "精确"是个需要重新定义的说法：Exact on Paper 表明 7 个文档标为 exact 的特性仍会翻转 1.5% 左右的判分，与调度噪声同量级；FP8 KV cache 的翻转率是它的两倍多。跨域方案的对比实验必须带调度地板。
  2. 循环架构的并发收益来自"布局"而非"更多投机"：PackLoop 证明成本单位是"行"（读一次 KV），把投机位置塞进同一行就能接近免费，且完全精确。
  3. 跨版本迁移有了精确解：LiveLoRA 把 adapter 更新限制在 final block、保持 base 投影与低秩坐标不变，从而在数学上等价于全历史重算，发布加速 68.98×——缓存不必因版本更新而作废。
  4. 压缩的极致案例：2-bit SRFT 让 26.4B 循环 MoE 在 32GB Mac 上跑 1M token（19.49 GiB 峰值），说明"KV 必然放不下"往往是压缩不够，而不是物理极限。
