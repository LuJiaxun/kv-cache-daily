一、重点方向：混合注意力缓存（4 篇）

1. TideCache: Efficient Hybrid LLM Serving with Transparent Cache Management and Layer-Wise Streaming

  • 链接：https://arxiv.org/abs/2611.26619
  • 时间：2026-11-19
  • 方向：混合缓存 · 分层流式 · 显存重分配

摘要：混合架构已成为开源权重模型的主流，其全局注意力层与有界状态层维护异构缓存，各自的需求随上下文长度与并发变化。TideCache 是跑在 CPU–GPU 超片上的服务系统，三个组件共同解决"GPU 内存如何在各缓存间分配、驻留如何跨 GPU 与主机内存管理"：透明缓存池在固定虚地址背后重新分配物理页，从而保住缓存布局与后端接口不变；缓存流式器利用有界状态层提供的计算间隙，把下一个全局注意力层的前缀预取到被多个全局注意力层共享的 GPU 槽位，在降低 GPU 驻留的同时把逐层传输与计算重叠（已生成的 KV 保持常驻）；请求调度器按请求大小与队列状态选择驻留式或流式执行，并触发容量调整。三者合力让被流式释放的 HBM 能容纳其他缓存组件与更多请求。在 SGLang 上实现、GB300 与 GH200 上七种模型/平台配置评估：相比带 HiCache 的 SGLang，完成最多 2.04× 的 agent 轮次、P50 每 token 延迟降 20%–59%、agent P50 TTFT 提升 1.40–3.05×。

对广域的启示："用有界状态层的计算间隙做预取" 是跨域可以照搬的排程思想——混合模型每隔几层就有一次便宜的计算窗口，正好用来搬运下一层的远端前缀。跨域取数如果能对齐到模型的层周期，就能把传输藏进计算里，而不是额外增加停顿。

2. RadixFlow: Filling Execution Bubbles in Prefix-Cached Hybrid LLM Serving

  • 链接：https://arxiv.org/abs/2610.18143
  • 时间：2026-10-13
  • 方向：前缀匹配 · 状态就绪 · 队头阻塞

摘要：前缀复用通过共享公共前缀的 KV 来提速，但这只有在调度器能把匹配到的分支排进当前 worker round 时才有用。现有调度器假设"匹配到的前缀已经就绪"——这在全注意力模型成立，在混合模型不成立：某个分支（消费者）可能需要另一个分支（生产者）在同一轮里还在计算的循环状态。原生调度器的等待队列扫描会在这个被阻塞的消费者处停下，由此产生的队头阻塞形成"执行气泡"（本可被独立工作填满的空闲 batch 槽位）。RadixFlow 把前缀匹配与状态就绪解耦：它的 state-ready 遍历把全局扫描屏障变成局部等待——只有该消费者被推到下一轮，而可行的独立分支在原生状态检查下继续填满 batch。五个混合模型上，平均延迟降 3%–24%、worker 轮次降 11%–44%，而复用率几乎不变；在更大的 Qwen3.5 上消融显示大部分收益来自遍历本身，在全注意力对照上增益很小；更重的轮次会限制这部分节省传导到延迟。

对广域的启示：这篇给出了一个被普遍忽视的区别——"缓存命中"不等于"状态可用"。在跨域场景里这个区分更尖锐：前缀可能远在另一个 region 且还没算完状态。调度器应当把"匹配"与"就绪"分开建模，否则会把整个批次卡在一个远端未就绪的分支上。

3. GateSight: Recurrent Memory Anticipates Attention Memory for Query-Agnostic KV Eviction in Hybrid LLMs

  • 链接：https://arxiv.org/abs/2610.14754
  • 时间：2026-10-10
  • 方向：混合模型驱逐 · 写入门信号 · 查询无关

摘要：混合语言模型把固定大小的循环记忆（Gated DeltaNet，GDN）与随上下文增长的注意力 KV 交错。论文问了一个很漂亮的问题：循环记忆是否已经知道注意力记忆将来需要什么？先证明 Qwen3.8-27B 里"哪些 GDN head 保留长期记忆"由权重而非文档决定；再把一个 KV 条目的未来效用定义为"删掉它后模型自续写上的注意力输出变化"，发现 GDN 层在 prefill 期发出的写入门、衰减与写幅在任何查询出现之前就能预测该效用。由于这一关系分散在多个 GDN head 与层上，线性映射只能恢复趋势、恢复不了高效用尾部，GateSight 用轻量的 per-head MLP 读取这些信号（不读注意力分数）来学它；预测出的效用决定各注意力层保留哪些条目，而保留多少由模型原生注意力输出门的均值决定（该均值跨层差一个数量级以上）。服务时在 prefill 之后给缓存打一次分并物理释放被丢弃的条目。SCBench 与 RULER-4096、Qwen3.8-27B（含稀疏注意力变体 Qwen3.8-Flash-Next）、直到 262K token：只用十分之一注意力 KV，GateSight 在四组模型-基准对中三组为五种查询无关方法里最准，四组全部领先 KVzip 9.5–47.2 分；给全长上下文打分相对 prefill 的开销可忽略。

对广域的启示："免费信号"是跨域驱逐的最优依据——写入门/衰减这些量在 prefill 时已经算出来，不需要额外传输或探测。更重要的是它实现了"用户问题到之前就知道该留什么"，这对跨域尤其关键：可以在请求到达前就决定同步哪些 KV，而不是等查询来了再做二次调度。

4. LSTM-Style Looped Transformers with Shared KV Caches

  • 链接：https://arxiv.org/abs/2610.33360
  • 时间：2026-10-23
  • 方向：循环权重共享 · 共享 KV · 训练一致性

摘要：循环 transformer 通过复用权重以更少参数做更深计算。论文研究一种 LSTM 风格的 transformer，其循环核也共享同一份 key–value 缓存。宽度 1024 时，它比未绑定的对照少 40.4% 参数、前向 FLOPs 几乎持平，并把持久缓存集从 15 个减到 4 个。并行训练用标准注意力的一次 pass 提供缓存条目，而续写阶段读取的是用共享注意力递归产生的条目，两者存在错配；作者用固定 token 预算最后 10% 上的一致性损失对齐两个训练 pass 的缓存条目，在 FineWeb 的三个宽度上消除了相对全缓存评估的 81%–89% 续写损失惩罚，并在两个训练种子上用不相交文档复现。四种宽度、1.05–4.19B 训练 token 下，权重绑定在较低 token 预算时损失代价最小——提示在数据与模型存储受限时更适合用循环计算。

对广域的启示："少几份缓存"是架构级的省钱——持久缓存集从 15 降到 4，意味着跨域要同步的状态种类直接少一个数量级。这比任何压缩算法都彻底：它改变了需要管理的缓存数量，而不只是每份的大小。

二、压缩与量化（2 篇）

5. QuantStream3D: Geometry-Aligned Low-Bit KV Cache Quantization for Streaming Visual Geometry Transformers

  • 链接：https://arxiv.org/abs/2611.27901
  • 时间：2026-11-20
  • 方向：流式 3D · 几何对齐 · 混合精度量化

摘要：流式视觉几何 transformer 把历史 KV 状态当作跨视图几何记忆保留，但增长的缓存限制了长序列推理。论文系统刻画了流式几何中的 KV 量化，指出两个相互关联的挑战：非均匀几何敏感度（敏感度随精度选择与缓存位置变化）与缓存-几何错配（被扰动的检索改变几何 head 的输入，并沿后续预测与 KV 写入传播）。据此提出 QuantStream3D，据称是首个专为流式几何 transformer 设计的 KV 量化框架：几何引导的混合精度量化保护敏感的跨视图证据，几何对齐的量化感知蒸馏在学生自生成的量化历史上联合适配 transformer 块与几何 head。五个基准、两个 backbone 上，多数设置下以主要是 2-bit 的 KV 缓存达到接近无损的几何精度，不少配置甚至超过未量化推理；相比面向 LLM 的 KV 量化器，TUM 绝对轨迹误差与 NeuralRGBD 完整度误差分别最多降 57.4% 与 69.7%；与原生缓存剪枝结合还能进一步压缩并在 NeuralRGBD 上提升重建质量。优化后的 StreamVGGT 后端实现 5.05× 物理 KV 压缩、batch=1 时延迟降 23.1%；同 GPU 固定内存预算下支持 5.4× 的最大 batch 与最高 1.67× 峰值吞吐。

对广域的启示："量化误差会沿着下游写出新的 KV"——这是流式几何特有的反馈回路，却提示了一个通用问题：跨域压缩不能只看静态重建误差，还要看误差是否会被写回缓存继续传播。有状态任务（3D、视频、agent）都应注意这条回路。

6. Preserving Updates in Low-Bit Recurrent State Quantization

  • 链接：https://arxiv.org/abs/2610.15709
  • 时间：2026-10-11
  • 方向：循环状态量化 · 误差累积 · 有界方向取整

摘要：线性注意力与循环模型把历史压缩成每步都要更新的固定大小状态；高精度存储在大 batch 下带来可观的内存与带宽成本，因此需要低比特量化。与权重和 KV cache 不同，循环状态每次更新后都要重新量化，量化误差会跨步累积。分析表明这些误差高度相参（coherent），所以仅降低单步误差不够——相参主要来自在取整中被丢掉的小更新。论文在取整前后各做一次干预：取整前用低秩旁路（LRB）把小更新累积进紧凑的低秩缓冲、定期把足够大的元素并入状态；取整时观察到状态元素甚至会朝更新的反方向移动，这种反转特别有害，于是用有界方向取整（BDR）把反转元素朝其更新方向取整（不增加存储）。虽然 BDR 增大了单步取整误差，模型却变好——说明更新方向比单步误差更重要。在 Gated DeltaNet、GLA、Mamba2、RetNet 上，该免训练方法显著优于 INT4，状态内存最多降 5.3×、解码比 FP32 状态快 1.9×。

对广域的启示：循环状态是可压缩的，但要保住"更新方向"。跨域同步循环状态时若用有损格式，必须保证"增量方向"不被抹掉，否则误差会沿解码步累积——这与 KV 的"静态"压缩有本质区别。

三、容量与记忆（2 篇）

7. KV-LTM: Persistent Per-Session KV Caches as Long-Term Memory for Personal Assistants

  • 链接：https://arxiv.org/abs/2611.21998
  • 时间：2026-11-16
  • 方向：持久会话缓存 · 长期记忆 · 容量测算

摘要：个人助手会累积数月的对话，而当前长期记忆栈在"问题"与"证据"之间插入了推导或选择环节。LongMemEval 上的系统级对比显示，两个商用助手的得分远低于同一模型离线读完整历史——这与"写入与读取之间存在内容损失"一致，但并不能单独证明。论文提出 KV-LTM：一个记忆层，保存每个会话的原始文本加上其 KV cache（固定 reader 模型），回答时恢复被缓存的会话并附上问题。KV-LTM 与检索/索引是互补而非替代：文本才是记录本体，缓存只是免重算的 prefill 加速器，可优雅退化为纯文本。论文给出设计（存储记录、按预算推导的保留策略、只追加的读路径、有界聚合）并做解析式容量测算：在固定的 BF16 全注意力（GQA）与 latent 缓存（MLA）配置下，每 token 状态约 31K–328K 字节；而固定的 KDA+MLA 混合配置约 8.1K 字节/token 加一个固定的每会话循环项。按声明的每天 30K token 场景，约 0.34–3.6 TB 每用户每年，对比原始文本仅约 49 MB；每查询成本按 regime 分别建模为传输、注意力、解码、聚合与计算。

对广域的启示：这是本方向最直接的跨域容量账本：同一份"记忆"用文本只要 49MB/年，用 KV 要 TB 级——差 4 个数量级。它同时给出混合模型的每 token 状态量（约 8.1KB，比 GQA 的 31K–328K 小一个量级），再次说明混合架构在跨域存储上更有优势。

8. MemOnce: A Scalable Memory Architecture for Large Language Models

  • 链接：https://arxiv.org/abs/2611.27973
  • 时间：2026-11-20
  • 方向：记忆编解码 · 动态解回 KV · 稀疏检索

摘要：在长程与持续交互中部署 LLM 需要为后续推理保留可复用记忆状态。标准 transformer 累积逐层、逐 token 的 KV cache，显存线性增长、计算二次增长；线性时间架构把历史压成固定大小状态，却难以保住细粒度细节。MemOnce 是一个学习可扩展记忆状态的基础架构，两个核心设计：①记忆编解码器——只缓存最后一层隐状态的一个小子集作为紧凑记忆表示，并动态解码回各注意力层的 KV cache；②记忆稀疏注意力——对每个持续输入自适应检索相关记忆表示，且稀疏索引只跨层计算一次。二者耦合实现即时记忆加载与 KV 解码，大幅压缩显存并取得线性时间。多种模型规模、上下文长度与训练范式（预训练与后训练适配）上优于 transformer 与其他架构；特别地，用 MemOnce 适配 Qwen3.5-4B，在 1M 上下文下记忆状态缓存减 1313×、prefill 延迟降 6.9×，吞吐提升 3.5×、整体记忆性能 +5.77%，并零样本迁移到下游表示任务。

对广域的启示："存一份小的、用时解出大的" 正是跨域最需要的形态——1313× 的存储缩减意味着跨域只需同步紧凑记忆，各节点在本地解码出自己需要的 KV。这与之前收录的 AnchorKV（传锚点重建）是同一思路的不同层级实现。

四、诊断与生成（2 篇）

9. Where KV-Cache Error Lives in Looped Language Models: A Diagnostic Study of Ouro and Huginn

  • 链接：https://arxiv.org/abs/2610.41825
  • 时间：2026-10-30
  • 方向：循环模型 · 误差定位 · 可复现性

摘要：循环语言模型每 token 把同一组层跑 4 次、每个循环各留一份 KV plane。论文研究存储误差在何处改变 next-token 分布、共享权重误差如何累积：Ouro-1.4B（4 循环）在 GSM8K 与 MATH、Huginn-0125（32 循环）在 GSM8K 衍生链上做稠密与模拟量化。单位误差下 value 承载了 94% 的对角 Fisher 质量，但实测 KL 主要由量化误差更大的 key 主导。局部二阶预测能跟上典型序列的实测 KL（含 136 条留出链），但漏掉少数高置信行；32 循环下共享权重的局部二阶因子在 1.65（INT8）到 4.09（INT4） 之间——取决于误差方向。一个 cell 级分配器在 25%–48% 的 BF16 字节下降低单步 KL，但配对的任务准确率对比依赖预算，且对 K4V2 的 25% 差距在事后答案抽取检查下缩到接近零。后续在 Ouro-2.6B 上的测试保留了 key/value 分裂的结论，却证伪了"实测代价分配优于 Fisher"在 31% 时的优势；在全部 21 条台账登记中，176 项判据有 60 项失败。

对广域的启示：这篇的诚实性本身是标杆：作者公开报告了自己的部分结论在更大模型/更严评估下不成立。对跨域决策的意义是——"按实测代价分配比特"未必优于按 Fisher 这类静态敏感度；不要在没有复现的情况下把单一论文的分配策略当作定论。

10. Hindsight Forcing: Learning Better History from the Future in Autoregressive Video Diffusion

  • 链接：https://arxiv.org/abs/2611.27074
  • 时间：2026-11-20
  • 方向：自回归视频 · 历史 KV 监督 · 梯度桥

摘要：少步自回归视频扩散支持实时流式生成，每个生成的 chunk 都作为后续生成的历史上下文。为避免时间反向传播的显存爆炸，此前的自 rollout 方法通常截断跨 chunk 梯度或 detach 历史 latent，结果是早期的去噪计算收不到"它写出的历史如何帮助后续生成"的下游反馈，rollout 变长时出现视觉漂移与结构崩塌。Hindsight Forcing 用latent straight-through 桥解耦前向生成与反向信用分配，让历史 chunk 直接从未来结果学习：前向时每个 chunk 完成完整的多步 rollout 以更新 KV cache；反向时桥把未来 loss 的梯度回传到每个历史 chunk 中选定的单个去噪步，在共享参数上同时训练上下文写入器与历史去噪器，而无需保留完整轨迹图。它不增加参数、不改架构、也不需要单独的轨迹回放。VBench 上整体视觉质量与动态运动优于现有基线，消融验证了监督历史去噪的收益。

对广域的启示："写进 KV 的内容要接受下游检验"——历史缓存不是只写不读的日志，它的质量决定后续生成。跨域共享的 KV 若来自别的节点/别的模型，同样需要用下游任务反馈来校准写入策略（呼应之前 Baton 的"可用性优先"结论）。

今日观察

  1. "命中 ≠ 就绪"成为混合模型服务的关键区分：RadixFlow 证明把这两个概念混在一起会造成队头阻塞与执行气泡；跨域场景里这个区别更致命（远端前缀可能还没算完状态）。
  2. 循环记忆可以做注意力记忆的"预言机"：GateSight 用 prefill 期就已存在的写入门/衰减信号预测 KV 未来效用，只用 1/10 缓存仍最准——这意味着跨域可以在请求到达前就决定同步范围。
  3. 架构级"减少缓存数量"比压缩更彻底：共享 KV 的循环 transformer 把持久缓存集从 15 降到 4；MemOnce 用"存小解大"把记忆状态压 1313×。
  4. 容量账本首次被量化到用户-年尺度：KV-LTM 给出 0.34–3.6 TB/用户/年 vs 文本 49 MB——跨域存 KV 还是存文本，差 4 个数量级。
