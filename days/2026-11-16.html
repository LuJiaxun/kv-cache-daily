一、跨广域 / 跨区域与边缘

1. An Internet for the KV Cache: Rethinking Classical Infrastructure Boundaries in the LLM Inference Age

  • 链接：https://arxiv.org/abs/2608.01526
  • 时间：2026-08-02
  • 方向：广域 KV 基础设施 · 计算存储解耦 · 成本模型

摘要：论文指出，agent、RAG、工具调用、多轮对话会反复访问重叠上下文，KV 复用能省掉大量 prefill；但模型侧“把 KV 变小”和系统侧“把计算/存储/传输变便宜”这两条线，一直被锁在传统云边界内各自演进。作者主张未来的推理基础设施应允许计算与 KV 存储跨云、跨数据中心解耦，让网络成为主动的分发通道：带宽、时延和价格直接决定 KV 该如何管理。论文给出一个可操作的决策框架：比较缓存成本与重算成本的比值，而这两个成本又取决于模型指标（prefill FLOPs、KV 大小）、基础设施指标（GPU/存储成本、网络带宽）和应用指标（复用频率、工具调用时长、对话轮数）。按博客中的算例：约 10 万 token 的 DeepSeek-V4-Pro，压缩后 KV 约 1GB，在满载 10Gbps 链路上传约 0.8 秒、AWS egress 约 $0.09；而在 8×B200 上重算约 15 秒、$0.47。

对广域的启示：这是把 KV 当“CDN 内容”的完整世界观——先算 CacheCost vs PrefillCost，再决定传、存、还是重算；跨域方案的设计目标也从“降时延”扩展为“在价格、带宽、复用频率之间做全局放置”。

2. SkyWalker: A Locality-Aware Cross-Region Load Balancer for LLM Inference

  • 链接：https://arxiv.org/abs/2505.24095
  • 时间：2025-05-30（EuroSys 2026）
  • 方向：跨区域负载均衡 · KV 局部性 · 昼夜流量

摘要：多区域部署 LLM 时，provider 通常用预留实例或自建集群，但区域本地流量处理＋昼夜波动会让资源利用率偏低。SkyWalker 用跨区域流量聚合来抹平各地区昼夜模式，使 provider 可以按全球期望需求而不是各地区峰值来预留容量；同时它要保住 KV cache 局部性与负载均衡。为此设计了两块：cache-aware 的跨区域流量处理器与selective pushing 的负载均衡机制。真实负载评估显示，相比现有负载均衡器吞吐提升 1.12–2.06×、时延降低 1.74–6.30×，总体服务成本降低 25%。

对广域的启示：跨区域调度不只是“把请求发到最近的地方”，而是在全局削峰、KV 命中、时延之间做联合权衡；“选择性推送”比全量重定向更能保住缓存局部性。

3. Efficient and Privacy Aware Edge Cloud Collaborative Inference for Large Language Models

  • 链接：https://arxiv.org/abs/2607.13093
  • 时间：2026-07-14
  • 方向：边缘-云协作 · KV 认证 · 加密传输

摘要：端侧推理面临时延、有限硬件与隐私的三难：全云推理算力强但暴露 prompt 与对话数据，纯端侧又跑不动。论文提出以端点认证的 KV cache 为核心的隐私协同框架：本地端负责输入预处理、embedding、自适应特征优化、KV 认证、推测解码与低维 head 计算；云端负责认证后的 decoder 推理、KV 管理、token 验证与高维词表投影；端点融合部分输出并采样。所有传输数据与截断 logits 都量化并用 AES-GCM 加密，核心轻量模块、draft 参数与缓存访问策略留在本地。框架支持纯 CPU、GPU 与嵌入式设备；相比基线 split inference，每 token 时延最多降 46.1%，下行 payload 最多降 67.4%，性能接近全云。

对广域的启示：KV 跨边缘-云传输时，认证 + 加密 + 量化要一起设计；把“谁能读这份 KV”编码进缓存本身，比只加密链路更适合多租户/多设备场景。

二、复用

4. To Cache or Not to Cache: Understanding and Mitigating Safety Incompatibility in Cross-Model KV Cache Reuse

  • 链接：https://arxiv.org/abs/2610.15721
  • 时间：2026-10-11
  • 方向：跨模型复用 · 安全兼容性 · 值对齐

摘要：跨模型 KV 共享让接收模型复用相关发送模型生成的 prefix KV，从而省掉 prefill；现有方法只优化时延与生成质量，安全影响不清楚。论文系统评估多种 sender-receiver 对与复用配置，把偏离接收模型原生安全行为称为 safety incompatibility：偏差方向与幅度取决于模型对和复用配置，且value 复用造成的偏差显著大于 key 复用。作者提出 VReparo：离线学习逐层、逐 KV 头的仿射映射，把复用的 sender value 对齐到 receiver 原生 value，再解码。两个模型对、全量复用与 SOTA 选择性复用设置下，HarmBench 平均攻击成功率从 57.28% 降到 39.21%，StrongREJECT 从 0.4215 降到 0.2163，同时保留平均 85.62% 的 TTFT 降幅。

对广域的启示：跨模型/跨版本共享 KV 时，安全对齐是独立于性能的一等指标；value 比 key 更“危险”，需要专门的校正层。

5. Dynamic Flow, Static Graph: KV Cache Reuse for Efficient LLM Serving on Mobile NPUs

  • 链接：https://arxiv.org/abs/2609.34727
  • 时间：2026-09-28
  • 方向：端侧 NPU · 前缀/非前缀复用 · 静态图

摘要：端侧 LLM 服务要求数据主权、隐私与低时延，但现有 KV 缓存设计主要面向云端 GPU 的动态执行与充足带宽；手机 NPU 的计算图必须静态编译，内存与 I/O 带宽都紧张。论文做计算-存储协同设计，同时支持 prefix 与非 prefix 复用：图内机制把选择性 KV 重算映射到静态 NPU 图上，调和算法动态性与 NPU 静态性；图间调度器用动态规划优化 chunk 合并、减少 padding；层次化 KV 管理器用 tree-hash-semantic 混合结构＋代价感知的预取/驱逐；再用二维流水线把 KV 加载、rerotation、存储与 NPU 执行重叠。代表性端侧负载上，TTFT 相比无复用/仅前缀缓存降低 40–60%。

对广域的启示：在算力与 I/O 都受限的边缘，复用必须和预取/流水线一起做；静态图约束下的“选择性重算”思路，也可迁移到跨域时“传一部分、算一部分”的取舍。

6. Shared-Prefix KV Reuse Across Standard LoRA Adapters: Quality and Serving Tradeoffs

  • 链接：https://arxiv.org/abs/2609.17109
  • 时间：2026-09-15
  • 方向：LoRA 多专家 · 前缀复用 · 实测权衡

摘要：常见的小模型部署是“一个共享 backbone + 多个 LoRA 专家”回答同一段上下文，朴素做法是每个专家都重新 prefill。论文研究一个很实际的问题：对已经训练好的标准 LoRA（不是为缓存兼容性重训的），如果 backbone 的 prefill KV 只算一次并跨专家复用，任务质量能保住多少、服务成本能省多少？在 Qwen3-1.7B + 两个 adapter（HotpotQA 抽取式 QA、GSM8K 算术）上扫描专家接管的边界：全前缀复用 prefill 成本最低，GSM8K 上有小幅质量差（160 token 预算 Δ=-4.6 EM，320 token Δ=-3.0，换种子 Δ=-0.8，均偏向原生，只有第一个排除 0）；部分重算没有显示出优势；闭式 ridge KV translator 也没有超过直接复用。服务收益体现在 warm-cache TTFT，随上下文增长（8K 时约 16×）；但两分支峰值内存只低 12%，因为实现复用了 KV 值却复制了存储，前缀并未真正共享。

对广域的启示：跨 LoRA 复用能显著省 prefill/时延，但不一定省内存；把“值复用”做成“存储共享”才是跨域缓存池真正需要的能力。

三、压缩

7. TraceKV: Policy-Preserving Low-Rank KV Cache Compression for Reasoning Vision-Language Models

  • 链接：https://arxiv.org/abs/2611.15569
  • 时间：2026-11-11
  • 方向：低秩压缩 · 推理 VLM · 策略保持

摘要：推理型 VLM 的 KV 同时被多模态长上下文和增长的推理轨迹撑大；低秩压缩能存低维 latent 并可叠加量化，但现有方法在压缩推理 KV 时会产生逐渐增大的预测策略漂移，导致推理失败。论文定位两个原因：静态上下文与 on-policy 推理状态之间的校准状态错配，以及不同 KV 状态的误差敏感度不均。TraceKV 是训练免费框架，把 on-policy 校准、敏感度感知 SVD 与全局秩分配统一在“策略保持”原则下，显著降低推理过程中的 policy-KL 散度。多个 VLM 与视觉推理基准上取得更优的准确率-内存权衡，叠加量化后 5.64× 压缩仍接近无损，优化后的低秩 attention kernel 还带来最高 1.83× 端到端解码加速。

对广域的启示：压缩要按“对策略/输出的影响”分配秩，而不是统一秩；对跨域传输，这意味着同样的字节预算可以优先保住推理链关键状态。

8. DepthWeave-KV: Token-Adaptive Cross-Layer Residual Factorization for Long-Context KV Cache Compression

  • 链接：https://arxiv.org/abs/2607.06523
  • 时间：2026-07-07
  • 方向：跨层分解 · token 自适应 · 长上下文

摘要：长上下文推理受 KV 的带宽与容量限制，但现有压缩常在各层/各 token 上用统一预算，当词法线索与语义状态需要不同保留策略时会伤检索。DepthWeave-KV 在相邻 Transformer 层之间用共享低秩通道基分解 K/V，同时对注意力敏感的位置保留轻量 token 专属残差；一个 token 条件深度路由器把更高的重建秩分配给指令承载与检索关键的 token；并用来自 attention-output 探针的无校准在线误差跟踪在生成中自适应压缩，无需重训。融合 CUDA 实现把基查找、残差反量化与 attention 投影合并，降低 decode 访存。LongBench、Needle-in-a-Haystack、L-Eval 等基准上接近全缓存质量，平均分与检索准确率优于先前压缩缓存，实现 8.3× KV 内存缩减、64K 上下文下 72.8 tokens/s。

对广域的启示：跨层共享基 + token 级残差把“层间冗余”与“关键 token 保护”结合，适合在传输前做非均匀压缩；在线误差跟踪让压缩比可以随内容动态调整。

9. Fast KVzip: Efficient and Accurate LLM Inference with Gated KV Eviction

  • 链接：https://arxiv.org/abs/2601.17668
  • 时间：2026-01-25
  • 方向：门控驱逐 · 低开销 · 长上下文

摘要：现有 KV 压缩常在“性能下降”和“计算开销”之间取舍。Fast KVzip 为冻结权重的 LLM 提出门控式驱逐：用轻量 sink-attention 门控模块识别并保留关键 KV 对，可无缝接入 prefill 与 decode 两个阶段；门控训练只依赖 LLM 的前向传播，避免昂贵的反向传播，并通过任务无关的重构目标获得较强泛化。Qwen2.5-1M、Qwen3、Gemma3 系列上，在驱逐最多 70% KV 的情况下保持近无损，覆盖长上下文理解、代码理解与数学推理。

对广域的启示：训练成本低、推理开销小的驱逐更适合在线服务；70% 的驱逐率意味着跨域传输字节可大幅下降，但需要按任务验证“证据链”是否还在。

10. KeepKV: Achieving Periodic Lossless KV Cache Compression for Efficient LLM Inference

  • 链接：https://arxiv.org/abs/2504.09936
  • 时间：2025-04-14（AAAI 2026）
  • 方向：合并压缩 · 注意力补偿 · 误差界

摘要：传统驱逐会丢信息、引发幻觉；基于合并的方法保留更多信息，但合并前后注意力分布不一致，会损伤生成质量。KeepKV 提出自适应 KV 合并：用 Electoral Votes 机制记录合并历史并自适应调整注意力分数，再用 Zero Inference-Perturbation Merging 补偿合并造成的注意力损失；在严格内存约束下实现单步无损压缩，并给出多步压缩的误差界。多种基准与模型架构上显著降内存，仅 10% KV 预算仍保持较好生成质量，推理吞吐提升 2× 以上。

对广域的启示：合并比驱逐更能保住信息，但需要显式补偿注意力；对跨域缓存，合并后的 KV 仍是“可解码”的完整状态，适合长期存放与复用。

今日观察

  1. KV 正在被当作“内容”而不是“中间张量”：Internet for KV 用 CacheCost/PrefillCost 做全局放置，SkyWalker 用跨区域流量聚合削峰，两者都把网络价格/时延放进了目标函数。
  2. 复用开始区分“省计算”和“省内存”：LoRA 复用的实测说明值复用可能仍在复制存储，跨域缓存池要的是真正的共享。
  3. 跨模型复用的安全代价被量化：value 复用比 key 复用更危险，VReparo 用逐头仿射校正把 ASR 从 57% 降到 39%。
  4. 压缩继续走向“结构化 + 自适应”：跨层共享基、token 条件秩、门控驱逐、合并补偿——单一固定压缩比的时代正在过去。
