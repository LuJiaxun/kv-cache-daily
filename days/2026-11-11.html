一、存储与地址空间

1. Range: Decoupling KV-Cache Reuse Granularity from Storage Work

  • 链接：https://arxiv.org/abs/2610.21241
  • 时间：2026-10-15
  • 方向：对象粒度 · 存储栈开销 · 前缀恢复

摘要：上下文变长把 KV 推过 GPU HBM 与 CPU DRAM，落到 NVMe SSD 上，前缀恢复因此落在 TTFT 的关键路径。论文发现，在配置良好的 host-issued 路径上SSD 并不是瓶颈：恢复同样 6 GiB 的 KV，按 192 个对象取是 2.1s，按 6,144 个对象取是 3.0s，分层加载时更差——因为存储栈的每一层（查找、分配、I/O 提交、GPU 交付、存储、索引）都在按逻辑对象计费，而字节数没变。这个开销会随 KV 体积放大：更长上下文、更深模型、张量并行都会乘上对象数。以往工作把这份按对象的开销从 CPU 挪到 GPU，但“按对象”这件事本身没变。Range 是以「存储栈上每一笔开销都不应随对象数增长」为原则构建的 KV 存储引擎（适配 vLLM 与 LMCache）。

对广域的启示：跨域取数同样会被“对象数”而不是“字节数”拖慢——把小对象合并成连续大块（更大分区、层主序布局）往往比提升带宽更有效。

2. Characterizing Predictability-Latency Trade-offs of KV-Cache SSD Offloading in LMCache

  • 链接：https://arxiv.org/abs/2610.21249
  • 时间：2026-10-15
  • 方向：卸载实测 · 页缓存 · 去重

摘要：KV 卸载被广泛用于扩展显存，但其块设备级行为缺乏刻画。论文用真实多会话负载（同/不同上下文 × 同/不同 prompt，每种超 100 个无状态请求）研究 LMCache，对比两个可实现的部署快照：0.3.0（缓冲 I/O + 内核页缓存）与 0.3.16（前缀感知去重 + O_DIRECT）。关键发现：旧栈在四种负载下看起来「几乎不读盘」，但 flush_ram 实验显示这依赖页缓存热度——一旦缓存被逐出，同一路径会在 683ms 内发出约 1GB 顺序读；去重的写缩减只对完全重复负载显著。

对广域的启示：性能数字高度依赖缓存是否预热；跨域方案的评估必须区分冷启动与热态，否则会把“页缓存红利”误读成传输优化效果。

3. UlaCache: Unified Logical Addressing for Sparse LLM Serving

  • 链接：https://arxiv.org/abs/2610.29820
  • 时间：2026-10-21
  • 方向：逻辑地址 · 异构内存 · 稀疏注意力

摘要：长上下文下 KV 使显存承压；token 级稀疏注意力能减少注意力计算与访存，但 KV 条目仍需保留供未来查询，存储容量依然限制解码并发。GPU+CPU 组合内存可以扩容，但跨异构内存池的高效访问是难点。UlaCache 提供跨 GPU 与 CPU 内存的统一逻辑寻址：其逻辑槽位接口让推理引擎用稳定标识分配、写入、访问、释放 KV 条目，对注意力并行模式透明；UlaCache 负责物理放置、驻留与传输，并在 KV 迁移后更新地址映射。配套的 Parallel Bucketed LRU（PB-LRU）把最近使用信息更新的开销并行化。

对广域的启示：把“地址”和“位置”解耦，KV 迁移就变成透明的重映射；这正是跨域缓存池需要的能力——应用只认逻辑句柄，调度器决定它此刻在哪个 region。

二、压缩与重建

4. AnchorKV: Lossless Key-Value Cache Reconstruction from Layer-Sparse Residual Anchors

  • 链接：https://arxiv.org/abs/2611.00117
  • 时间：2026-10-28
  • 方向：无损重建 · 残差锚点 · 架构相关

摘要：残差流缓存可以无损重建 KV，但其内存优势取决于架构。AnchorKV 给出一个存储-重放的连续谱：通过可配置的残差锚点，在“每层都存残差”和“完全重算”之间取值；一条依赖架构的盈亏平衡规则给出第一个省存储的间隔，部署时可在谱上选工作点，并用级联重放把重建复杂度从 O(Ls) 降到 O(L)，其中 L 为层数、s 为锚点间隔。对交错滑窗架构，用精确动态规划在非均匀重建需求下布置锚点。跨 CPU、CUDA、Ascend NPU 后端、六个架构族、fp32/bf16 的评估验证了逐位精确的 KV 重建与不变的后续 logits/token；4k 上下文下级联重建比朴素重放快 16.3 倍。

对广域的启示：如果 KV 能由少量锚点无损重建，那么跨域只需传锚点、接收端本地重建——把带宽换成算力，这在 GPU 空闲率高、链路紧张时是很好的取舍。

5. BellowsKV: One Latent for Many Layers, Expanded on Demand

  • 链接：https://arxiv.org/abs/2610.35023
  • 时间：2026-10-26
  • 方向：跨层共享 · 按需展开 · 高压缩比

摘要：agent 多轮、工具调用与长任务让 KV 成为显存主要瓶颈。多数压缩方法在单层内工作——量化、降通道维、淘汰 token，但在高压缩比下三者都明显掉精度；跨层共享把一份压缩缓存供给相邻层，能突破这个上限，但高压缩比时同样急剧退化。论文发现关键处不在“层间 KV 相似”，而是相邻层的输入隐状态高度相似：因此 BellowsKV 共享的是隐状态层面的一个 latent，再按需展开成各层 KV，而不是强行让相邻层共用同一份 KV 表示。

对广域的启示：压缩的正确对象可能是层的输入而不是层的输出；这类“共享+按需展开”的结构，让一份传输对应多层缓存，跨域带宽按层数摊薄。

6. MoEZip: Routing-Aware KV Cache Compression for Sparse Mixture-of-Experts LLMs

  • 链接：https://arxiv.org/abs/2610.30206
  • 时间：2026-10-21
  • 方向：MoE · 路由敏感度 · Fisher 度量

摘要：MoE 通过每 token 激活少量参数来高效扩展容量，但长上下文下 KV 仍随序列线性增长。现有 KV 压缩方法主要针对稠密 Transformer，忽略了一个 MoE 特有风险：KV 淘汰会改变生成时被选中的专家，从而损害质量。MoEZip 提出用路由分布的 Fisher 信息矩阵来度量专家路由对扰动的敏感度，把它与注意力权重结合做路由感知的上下文打分，最后组合出兼顾稠密与稀疏 MoE 架构的互补评分体系。

对广域的启示：对 MoE 模型做跨域压缩/驱逐时，必须监控路由是否漂移；否则会出现“准确率掉了但看不出原因”的隐性退化。

7. RIFT: KV Cache Compression for Draft Models with Complementary Compressibility Training

  • 链接：https://arxiv.org/abs/2610.31098
  • 时间：2026-10-22
  • 方向：推测解码 · 草稿模型 · 解码陈旧

摘要：推测解码是长输出生成的重要加速手段，而长输出又需要越来越大的 KV。以 prefill 信息为中心的压缩方法会随着输出变长而失去相关性，论文把这一现象称为 decode staleness，并证明它会在基于选择的 KV 压缩下损害草稿模型准确率。RIFT 是一族基于选择的压缩策略，在「prefill 信息」与「近期生成的 token」之间做平衡；实验显示在生成过程中刷新 KV 选择能显著提升草稿质量，代价是额外的解码延迟，因此作者引入自适应刷新策略，在保持质量的同时减少打分次数。

对广域的启示：压缩策略要随生成长度演进，静态压缩比在长输出下会悄悄失效；跨域缓存若按固定压缩率存储长会话，需要定期“重新打分”。

三、负载刻画与跨模型复用

8. Cache Engineering for Agents

  • 链接：https://arxiv.org/abs/2610.28577
  • 时间：2026-10-20
  • 方向：Agent 主动控制 · 免重算 · 轨迹不变

摘要：agent 轨迹变长后，KV 的 I/O 与存储成为主要成本，轨迹还可能超出模型最大上下文，需要控制活跃缓存的增长。以往用 context engineering 通过裁剪或摘要历史来缩小缓存，但修改轨迹前缀会使后续缓存状态失效、触发昂贵的重新 prefill，保留太少上下文又会掉准确率。论文提出 cache engineering：让 agent 直接控制自己的活跃 KV，在不修改轨迹、不重新 prefill 保留上下文的前提下操作缓存——例如用 drop 把选定缓存排除在后续注意力之外，用 repos 调整保留 key 的位置等。

对广域的启示：把缓存控制权交给应用层，等于让“传什么、留什么”由业务语义决定，而不是由系统盲猜；跨域场景下这能显著减少无意义的同步。

9. Understanding KV Residency in Production-Scale Agentic LLM Workloads

  • 链接：https://arxiv.org/abs/2610.22863
  • 时间：2026-10-16
  • 方向：生产刻画 · 长会话 · 容量估算

摘要：agent 应用把一次用户请求拆成一系列模型与工具调用，上下文不断增长；把这份上下文的 KV 留在显存里可以让后续调用复用，但在集群规模下需要巨量内存。论文刻画微软 M365 的四个生产负载（Deep Research、Enterprise Assistant、Coding Agent、Enterprise Chat），覆盖超过 1.21 亿次模型调用。在 Deep Research 中，应用本身发出 89% 的模型调用，中位上下文到第 30 次调用时从约 10K 增长到 68K token；约 80% 的上下文 token 由前缀缓存提供。用公开的 Llama-2-70B KV 布局代替保密模型估算，单个 p99 Deep Research 会话就超过一张 H100 的 80GB HBM，若把所有活跃会话都按峰值驻留需要约 501.8 TB HBM，而推理实际只占用 5.6%。

对广域的启示：这是最有说服力的容量数据——不能按峰值驻留规划，必须按复用概率分层；否则要么 HBM 爆炸，要么全部外溢到广域链路。

10. Close Enough is Nowhere Near: Fidelity-Consumability Decoupling in KV Caches

  • 链接：https://arxiv.org/abs/2610.22016
  • 时间：2026-10-15
  • 方向：跨模型复用 · 可消费性 · 负结果

摘要：多 agent 系统以文本通信，既有损又浪费——发送方丢掉了自己已经完成的“阅读理解”。已有研究转而传输 KV 缓存。论文研究其中最诱人的形式：两边模型都冻结，发送方的缓存被直接替换给接收方、不做任何训练。它不成立，而且障碍在接收方：冻结的 Transformer 只读得动与自己会写出的缓存足够接近的那一片区域（称为其 tolerable set）；论文进一步证明，与该缓存的几何相似度并不能预测接收方能否使用它，且失败不是渐进的，所以“造一个更保真的替代品”并不是解法。作者用竞争性注意力解释这一现象，并用八种替换方法与两个实测锚点（无信息缓存基线、接收方自身准确率）做对比。

对广域的启示：这是跨模型/跨节点共享 KV 的重要冷水——“看起来像”不等于“能被消费”。跨域复用要么保证同模型同版本，要么必须引入训练过的适配（如仿射校正），否则收益是幻觉。

今日观察

  1. 对象粒度被确认为隐藏成本：Range 证明同字节数下 192 个对象 2.1s、6,144 个对象 3.0s，说明跨域取数应优先减少对象数。
  2. 地址与位置解耦：UlaCache 的逻辑槽位让 KV 迁移对上层透明，这是把本地池化扩展到跨域池化的前提。
  3. 无损重建打开“传锚点、算 KV”的新路径：AnchorKV 实现逐位精确重建，跨域可以把带宽换成算力。
  4. 跨模型复用被证伪于“零训练”形式：Close Enough 论文指出可消费性与几何相似度解耦，提醒跨域共享必须同源或带适配。
