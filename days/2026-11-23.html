一、重点方向：混合 / 循环注意力的缓存复用（3 篇）

1. FrontierReplay: Split-Free Exact Prefix Caching for Hybrid Language Models

  • 链接：https://arxiv.org/abs/2611.26020
  • 时间：2026-11-19
  • 方向：混合模型 · 精确前缀缓存 · 无切分重放

摘要：混合语言模型把自注意力与原地更新状态的循环层结合，后者使前缀复用只能停在已保存的精确位置上。在粗粒度网格上存状态会浪费可复用前缀；而现有细粒度精确缓存必须在 prompt 中间的每个 checkpoint 处切断 prefill 前向，增加的调度步数在负载下会吃掉复用收益。论文观察到：在多轮对话、agent 循环、文档问答、树搜索中，前缀复用几乎总是终止于可提前预知的结构边界（轮次结束、已知分支点）。FrontierReplay 因此在这些边界上物化精确 checkpoint 而不切断 prefill：前向不中断地跑，同时记录一小段循环层输入窗口，然后调用跨层、只作用于状态的 replay kernel 构建目标状态——每 token 比全量重算便宜 6–37×，且无需主机同步。

对广域的启示：这篇给了跨域复用两个可直接借用的点：①复用点应当按结构边界（轮次、分支）布设，而不是按固定 token 间隔，这样 checkpoint 数量少且可预测；②状态可以"现场重放"而不必"提前存好"——跨域只传少量 anchors，接收端用便宜的重放 kernel 补出完整状态，把带宽换成算力。

2. Just Let Linear States Forget the Distant Past: Prefix Caching via Suffix Replay for Hybrid LLMs

  • 链接：https://arxiv.org/abs/2609.33477
  • 时间：2026-09-27
  • 方向：混合模型 · 后缀重放 · 检查点替代

摘要：混合 LLM 里全注意力的 KV 是 token 可寻址的，而线性注意力层维护的循环状态无法回滚到任意前缀边界；现有系统只能物化循环状态 checkpoint，把复用限制在 checkpoint 对齐的位置。论文给出关键数字：Qwen3.5-4B 里一个线性注意力状态 checkpoint 约 49 MiB，而单 token 的 KV 只有约 32 KiB，相差约 1500 倍——所以不可能每个 token 都存。SuffixReplay 的洞察是"就让线性状态忘掉远古"：现代线性注意力用递归衰减与门控压制旧输入影响，因此可以用重放近期一段输入后缀来近似匹配边界处的状态，而不必 checkpoint 每个边界。系统层用独立管理的 anchor sidecar 与流水线重放路径，把 anchor 搬移与状态重建和原生服务流水重叠。在 OLMo-Hybrid-7B、Qwen3.5-4B、Qwen3.6-27B-FP8 上，LongBench 与 RULER 平均保留全 prefill 质量的 91.4%–100%，而摊销到每 token 的存储只有 SGLang 默认 8192-token checkpoint 缓存的 0.36–0.51×；集成进 SGLang 后，分支负载上中位 TTFT 降 15%–70%，工作集超出 HBM 时吞吐达 SGLang 的 2.3–4.3×。

对广域的启示："传 anchor 不传状态"在跨域上收益极大——anchor 是"层输入隐状态的一小段"，比 49 MiB 的完整循环状态小得多；接收端重放即可。这也解释了为什么混合模型的跨域复用可能比全注意力更划算：需要过网的字节少了一个数量级。

3. Fold the Loop: Decoding-Time KV Memory for Looped Vision-Language Models

  • 链接：https://arxiv.org/abs/2611.25369
  • 时间：2026-11-19
  • 方向：循环 VLM · 沿递归轴压缩 · 模块内共享

摘要：循环 VLM 通过反复应用权重共享模块来加深视觉推理，但解码内存随递归深度增长，限制了可放的图像尺寸与 batch。每次递归步都产生自己的 KV 状态，于是缓存里存了同一张图像的好几份拷贝。论文发现：精确 prefill 之后，较早的步仍然需要访问视觉信息，但可以复用同一模块内最后一次递归的视觉 KV。据此提出 FoldCache：沿递归轴压缩视觉 KV，同时保留完整的 prefill 计算。它把每个模块内的递归步分组，保留每组的最终视觉 KV 供组内成员在解码期共享；共享只发生在模块边界内，而问题与答案的 KV 仍按步独立。分组粒度控制压缩程度，且可与 token 驱逐、量化叠加。

对广域的启示：同构冗余是免费压缩——同一图像在多个递归步的 KV 高度重复，跨域传输时只需传"每组最后一份"。对循环架构的跨域部署，这意味着字节数按递归深度分组摊薄，而不是线性放大。

二、压缩与驱逐（3 篇）

4. Aggron: Aggressive Compression of Agentic KV Caches during Head-of-Line Stalls in the Request Queue

  • 链接：https://arxiv.org/abs/2611.26435
  • 时间：2026-11-19
  • 方向：Agent 负载 · 停顿期压缩 · 侧队列调度

摘要：LLM agent 运行长多轮程序，上下文每步增长，服务受 KV 容量限制。常见做法是等 KV 超过一个大阈值后一次性摘要一大段历史，要么在后台做、要么放在关键路径上；若用同一引擎上的同一模型做摘要，它还要与正在服务的请求争抢算力与显存。Aggron 的做法是：在 agent 的每一轮都做摘要，但只选择性地摘要 KV 的某些部分，从而保住精度、让摘要请求保持轻量。更关键的是调度——它把摘要任务从侧队列发起，正好利用主请求在正常队列里队头阻塞停顿时本来闲置的算力与内存；当系统预测某次摘要能在停滞 agent 恢复前完成时，才只压缩那部分缓存。

对广域的启示：把压缩放在"等"的空隙里——agent 等工具返回、请求排队时，正是做压缩的窗口。跨域链路上同理：传输空窗期可用于在源头压缩或重组，而不是等到带宽紧张时才动手。

5. RoCoKV: Uncertainty and Redundancy Aware KV Cache Compression

  • 链接：https://arxiv.org/abs/2611.25433
  • 时间：2026-11-19
  • 方向：推理模型压缩 · 不确定性引导 · 冗余感知

摘要：大推理模型的主要成本来自长推理轨迹而非输入 prompt，而轨迹里因循环、自验证、纠错产生了大量冗余低效用 token——问题在于这些 token 仍可能拿到高注意力分数，按注意力删就会伤推理。RoCoKV 有两个组件：不确定性引导的自适应剪枝按模型置信度调整压缩强度（不确定阶段多给内存、自信时更强剪枝）；冗余感知的 token 选择降低与近期推理内容高度相似 token 的影响，鼓励保留更有信息量、更多样的 token。此外还与服务栈做了协同设计。

对广域的启示：压缩强度应随"模型此刻有多确定"动态变化。跨域传输若能做到"不确定的段多传、确定的段少传"，就能在同样字节预算下保住推理质量。

6. Global Importance Estimation for KV Cache Eviction

  • 链接：https://arxiv.org/abs/2611.24969
  • 时间：2026-11-16
  • 方向：驱逐 · 多跳重要性 · PageRank

摘要：KV 的内存占用是长上下文推理的核心瓶颈。论文提出 PRKV：一个免训练的 KV 驱逐方法，通过在注意力诱导的转移图上运行 Personalized PageRank 来估计多跳全局 token 重要性，从而把重要性传播扩展到"新近度或瞬时注意力"之外，且不改动模型。在长上下文理解、稀疏检索与思维链推理任务、多个模型族上评测：中等到激进压缩比（含最高 90%）下，PRKV 与既有驱逐基线相比保持有竞争力的任务表现，同时降低峰值内存且端到端开销低。

对广域的启示："重要"不等于"被最近关注"——多跳传播能识别那些当前注意力不高、但支撑后续推理的关键 token。跨域缓存若按瞬时注意力淘汰，容易把这些"沉默的关键上下文"删掉，之后再传就得重算。

三、Agent 与多模态系统（2 篇）

7. TripleKV: Predict, Prefetch, Protect — KV Cache Management for AI Agents

  • 链接：https://arxiv.org/abs/2611.25112
  • 时间：2026-11-18
  • 方向：Agent 三层缓存 · 延迟预测 · 预取

摘要：agent 在推理与工具执行间交替，反复复用不断增长的上下文；高并发下它们的 KV 工作集可达数百 GiB，远超 GPU 容量。空闲 KV 块被逐到更慢的存储层后，返回的 agent 要为检索付出昂贵停顿。TripleKV 是三层 KV 管理系统，专门隐藏这些检索延迟：在 agent 负载里，下一次推理需要的 KV 块是提前已知的，只有复用时间不确定。TripleKV 用工具感知的延迟预测器估计每次工具调用何时完成，并提前把所需 KV 块从 SSD 预取到主机 DRAM；与 GPU 预取不同，这不占用稀缺显存、也不干扰并发推理。

对广域的启示："要什么已知、何时要未知"是 agent 负载的本质特征。跨域预取同样应该按工具调用的预期时长来排程——而不是按固定节拍——这样既能提前到位又不会长期占用带宽。

8. Do Thinking VLMs Need to Keep Looking at Long Videos? Write It Down, Then Look Away

  • 链接：https://arxiv.org/abs/2611.24259
  • 时间：2026-11-18
  • 方向：视频 VLM · KV 撤除 · 笔记替代

摘要：VLM 在数百到数千 token 的推理中理解长视频，而每个解码步都要重读整段视频的 KV。论文问：模型推理时必须一直"看着"吗？LookAway 让模型先写下"问题需要什么"的带时间戳笔记，然后把视频收起来——笔记结束后，推理引擎在剩余生成过程中隐藏视频的 KV 缓存。在混合与纯注意力 VLM 上都观察到：对视频的依赖集中在回答早期。Qwen3.6-27B 上，同一撤除步下写笔记比自由推理更好地保持精度；换成另一个视频的笔记会伤精度，而"既保留视频又保留自己的笔记"没有显著额外收益。无需额外训练，LookAway 以建模解码成本的 0.12–0.13× 接近完整"看视频推理"的精度。

对广域的启示："把感知结果写成文本/笔记，然后丢掉 KV" 在跨域场景极具吸引力——视频/长文档的 KV 往往是最占带宽的部分，而它们在推理早期的用途可以被少量 token 的笔记替代。这本质上是"用低带宽表示替换高带宽缓存"。

四、低比特量化（2 篇）

9. AscMLA: Unlocking FP4 Efficiency for Long-Context MLA Decoding through Asymmetric Scaling

  • 链接：https://arxiv.org/abs/2611.26106
  • 时间：2026-11-19
  • 方向：FP4 · MLA 解码 · 非对称缩放

摘要：长上下文解码反复读取不断增长的 KV。FP4 能同时降低缓存存储与流量，但其有限动态范围需要块缩放；把 FP4 用到 MLA 上还要调和共享 latent 上 K 与 V 不同的缩放需求。现有做法用反量化或分开编码来回避这一错配，带来额外执行或存储开销。AscMLA 用非对称 K/V 缩放 + 流水线式 scale 投递，直接处理单一 FP4 payload。相比 FP8，缓存内存少 38.2%；几何平均加速为 TRT-LLM FP8 的 1.35×、CAKE NVFP4 MLA kernel 的 1.26×。

对广域的启示：压缩态直接进 kernel是跨域的省上加省——接收端不需要先还原再计算。MLA 已成主流前沿模型形态，这类"单一 payload 直接执行"的设计能把跨域传输的字节与接收端算力同时压下来。

10. Online Temporal Rotations for 2 Bit KV-Cache Quantization in Video Diffusion Transformers

  • 链接：https://arxiv.org/abs/2611.26334
  • 时间：2026-11-19
  • 方向：2-bit 量化 · 视频 DiT · 在线旋转

摘要：视频扩散 transformer 在多个去噪步之间复用 KV，很快成为长视频生成的瓶颈。论文发现：量化时间上相距较远的缓存向量会导致量程过大、误差变高，但 KV 中时间相邻的视频 token 在每个通道上共享持续模式——且这些模式因视频而异，因此需要按视频适配的旋转。据此提出 Temporal Rotation Quantization（TRQ）：量化前先对时间上相邻的帧做旋转。对每个时间相邻的缓存块，TRQ 拟合一个正交变换，把该块的逐通道均值映射到近似跨通道恒定的向量；为保持量化格式轻量，把旋转参数化为 2×2 平面旋转树（每个只存 2 bit），后接一个共享的固定 Hadamard 变换。旋转无需梯度、不改模型权重，并证明简单贪心拟合对"均值压平"目标全局最优；变换对每个新视频在线拟合，并发布融合 Triton kernel。2-bit 精度、同等压缩下，VBench 主体一致性从 QVG 的 90.38 提升到 92.02（LongCat-Video-13B）、86.33 到 87.61（HY-WorldPlay-8B）。

对广域的启示：压缩要"按数据自适应"，而不是全局固定参数。跨域传输不同租户/不同模态的 KV 时，per-stream 拟合的轻量旋转（只存 2 bit 参数）几乎不增加传输开销，却能显著降低同样位宽下的失真。

今日观察

  1. 不存 checkpoint 成了混合模型复用的主流方向：SuffixReplay 用"重放近期后缀"近似状态，FrontierReplay 用"不切 prefill + 跨层重放内核"构建精确状态。两者都把存储换成算力，代价可控（6–37× 更便宜）。
  2. 数字给出了量级感：一个线性状态 checkpoint ≈ 49 MiB，而单 token KV 仅 32 KiB，差 1500 倍——这解释了为什么"传 anchor 让对端重放"是混合模型跨域复用的自然选择。
  3. 压缩时机在向"空闲窗口"迁移：Aggron 用队头阻塞的停摆期做摘要，TripleKV 用工具执行期做预取——都是把工作塞进本来浪费的时间。
  4. "用低带宽表示替换高带宽缓存"出现了明确证据：LookAway 用少量笔记替换整段视频 KV，解码成本降到 0.12–0.13× 仍保精度。
