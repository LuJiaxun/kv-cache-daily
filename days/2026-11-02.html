一、压缩：把「压多少」拆成「哪一层、哪一级、哪一种冗余」

1. Who Should Score the Cache? Mid-Depth Layers Are the Best Judges of KV-Cache Eviction

  • 链接：https://arxiv.org/abs/2611.02230
  • 时间：2026-11-01
  • 方向：驱逐 · 层深选择 · 注意力打分

摘要：KV cache 驱逐方法一律按注意力分数给 token 排序，而且每一层都给自己的 cache 打分，此前没有工作追问「该由哪一层来打分」。作者在 21 个模型上发现打分层所在的深度决定了驱逐质量：在 18 个使用逐层 cache、参数量从 0.5B 到 109B 的模型上，长上下文检索准确率在浅层崩塌、在 0.4–0.75 深度区间达到峰值、在最后一层又退化，原因是某一层只有先借若干层之力用问题定位到答案，才有能力判断 token 的价值。作者把驱逐建模为 top-$k$ 截断，从 prefill 注意力反推答案存活概率并复现了实测曲线，再用带已知答案的校准 prompt 选出打分层——所选层在多数模型上就是实测最好的层，且从不显著更差。相对「各层各打各分」的默认做法，该方法在 18 个模型中的 16 个上带来提升（其中 7 个显著，参数量均在 14B 及以下）；若统一由选中的中间层打分、所有 head 共用一组保留 token，在 14B 及以下 5 个模型的紧预算下比 per-head SnapKV 高 18–43 个点，在 32K 上下文的财报文本上同样成立且不需要额外前向。论文还给出共享 cache 结构的代价证据：Gemma-4-E2B 的写层偏浅，在 10% 预算下比中间层 reader 低 28 个点；而在 LongBench 开卷问答上没有任何中间层能超过「自己层打分」的默认设置。

对广域的启示：跨机房共享或集中式驱逐决策本质上是在替远端层「打分」，层深选错会带来几十个点的精度差；把打分层选择做进缓存策略的校准环节，比在传输侧省几个百分点的带宽更划算。

2. DepthGraft: Structural Regularization through Hierarchical Cross-Layer KV Reconstruction

  • 链接：https://arxiv.org/abs/2611.03142
  • 时间：2026-11-02
  • 方向：跨层 KV 共享 · 结构正则 · 预训练架构

摘要：加深层数是提升大模型能力的主路径，但 Pre-LN 架构常出现沿深度的信息稀释，使深层没有被有效利用；已有的跨层连接方案通常引入额外计算或访存开销。论文重新审视「跨层 KV 共享」这类零额外开销的连接：每条 KV 复用边都从深层向源 KV 投影建立了一条直接梯度路径，于是 KV 共享不只是省 cache，还成了 KV 表示几何的隐式结构正则项。作者系统分析该机制后指出，合适的共享拓扑能锐化 key 的检索方向、同时丰富 value 的内容子空间，而现有的相邻层共享或全局锚点共享并未充分利用这一效应。据此提出 DepthGraft：从 stride 对齐的浅层-中层源对重建深层 KV，把非局部梯度流分散到多个源层，同时保留 prefill 提前完成的能力。在 0.5B 到 16B 的 dense 与 MoE 模型上，GQA 与 MLA 两种注意力下下游指标均一致提升，KV cache 减少约三分之一；16B MoE 模型上 MMLU-Pro 绝对提升 7.0%，CMMLU 提升 6.6%，C3 提升 6.4%。

对广域的启示：跨层共享把缓存体积直接压到约三分之二，等于在缓存出口处先做一次无损减量，跨域传输量与驻留成本同比例下降；但收益依赖拓扑设计，跨节点复用同一份 cache 时必须保持拓扑一致，否则锐化过的 key 方向会被破坏。

3. CISA: Retrofitting Dense Attention Models with Chunk-Indexed Sparse Attention

  • 链接：https://arxiv.org/abs/2611.03200
  • 时间：2026-11-02
  • 方向：稀疏注意力 · KV 分块 · 免训练改造

摘要：长上下文推理昂贵，症结是注意力反复读取不断增长的 KV 历史。CISA 在不对预训练稠密注意力模型做任何梯度更新的前提下完成改造：它用已有 key 的紧凑摘要来选择固定大小的 KV 分块，避免 token 级索引，也不需要单独维护一份全长索引 cache；每个 KV 组只用一个索引 query，选中的分块在该组内所有 query 间共享。prefill 阶段还引入 QShare，在相邻 query 之间复用选择结果，进一步降低索引开销并提升 KV 复用率与 GPU 利用率。在 NVIDIA Nemotron 3 Nano、Ultra 与 Inkling-Small 上，单层 BF16、batch size 32 的基准中，1M token prompt 末尾附近的 prefill query 核心 attention 快 11.7 倍、decode 快 13.0 倍；把 chunk 打分与选择等全部 GPU 工作计入后分别为 8.6 倍与 3.0 倍。Ultra NVFP4 在 4,096 分块预算下，MRCR、LongBench v2 与 GraphWalks 的聚合分数与稠密注意力相差 1.5 个百分点以内；RULER 扫描到一百万 token 时分数相差 2.05 个百分点以内，KV 读取量少 8–16 倍。在四张 B300 上以 32 并发、每请求 4K 输出服务百万 token prompt，端到端吞吐为稠密注意力的 2.29 倍，进一步减少选中分块可到 2.61 倍，代价是 GraphWalks 聚合分数差距从 1.49 扩大到 3.59 个百分点。

对广域的启示：KV 读取量下降 8–16 倍，等价于跨节点、跨机房拉取 cache 的带宽需求同比例下降；「摘要先行、按需取分块」的形态也天然适配广域链路，只搬小摘要、按命中再取完整分块。

4. R$^2$-Omni: Reducing Structural and Precision Redundancy in Omni-LLMs for Long-Form Generation

  • 链接：https://arxiv.org/abs/2611.03247
  • 时间：2026-11-02
  • 方向：多模态压缩 · 结构冗余 · 精度分配

摘要：Omni-LLM 要处理大量音视频多模态 token，计算开销大，KV cache 显存占用尤其突出。激进 token 剪枝在多选类任务上能保住性能，但在长文本开放式生成上出现明显质量下降；作者归因于「query 引导的选择」：为了选出正确答案保留证据足够，却丢掉了完整生成所需的细节。由此提出减少 token 间重叠信息（结构冗余）而保留内容多样性，并进一步处理保留下来的表示中不必要的数值精度（精度冗余）。训练无关框架 R$^2$-Omni 分两级实现：结构感知 token 合并（STC）利用视频的时空相似性与音频的局部连续性合并冗余表示；语义敏感度引导的精度分配（SSPA）依据量化 key 下注意力输出误差的估计，为保留的表示分配 value 位宽，并用 query 注意力与视听对齐作为语义先验。在长文本生成基准上，平均显存占用降低 5.0 倍，同时保留 97.98% 的基线生成质量，端到端加速 1.48 倍。

对广域的启示：先把「结构冗余」在源头合并、再按语义敏感度决定「精度冗余」怎么降，这本身就是一套分级传输策略——粗粒度内容跨域搬、高精度细节按需补，比整份 cache 同精度同步更省链路预算。

二、复用与通信：让缓存跨请求、跨设备、跨轮次地流动起来

5. BasisKV: Value Latents for Communication and Key Routing

  • 链接：https://arxiv.org/abs/2611.02583
  • 时间：2026-11-02
  • 方向：低秩压缩 · 张量并行通信 · Key 路由

摘要：长上下文推理越来越受制于不断增长的 KV cache 成本，低秩 K/V 投影是少损失压缩的可行路线，但以往工作基本孤立地优化压缩，几乎没考虑分布式推理尤其是张量并行（attention 计算被切分到多张 GPU）下的落地问题。作者给出两个观察：一是把低秩 KV 压缩部署到分布式推理时，张量并行通信本身成为重要成本；二是 Value 压缩可以与输出投影绑定，从而让同一份低秩 Value 表示同时减小 Value cache 宽度与张量并行通信量。据此提出 BasisKV：针对完整注意力输出联合优化各 GPU attention 分区上的低秩因子，而不是逐个分区独立拟合；压缩后的 Value cache 还被复用来帮助判断该访问哪些 Key 页——它预测 Key 路由所需的部分 Key 信息，Key 专属残差保存无法从 Value 恢复的部分，随后只对被选中的页取回原始 Key 计算精确的 QK 分数。在多个模型族与系统设置下，BasisKV 的质量-效率权衡优于现有低秩基线，8 卡张量并行下端到端加速最高 1.42 倍。

对广域的启示：把「跨 GPU 传 KV」与「存 KV」放进同一个低秩优化目标里，正是广域场景该有的建模方式；让 Value 表示兼任路由索引、只对它命中的页取原始 Key，可直接迁移为跨机房 cache 的预取与按页拉取策略。

6. Fairway: Load-Aware KV Cache Reuse for LLM Prefill Scheduling

  • 链接：https://arxiv.org/abs/2611.02082
  • 时间：2026-11-01
  • 方向：前缀复用 · prefill 调度 · TTFT 尾部

摘要：agentic 工作流与 RAG 让请求从共享上下文构造长 prompt，serving 引擎据此复用 KV cache 以跳过部分 prefill。问题在于复用是分级的：队列中请求的未缓存工作量可相差 100 倍，而调度顺序直接决定各请求的首 token 时延（TTFT）。KV 复用优先调度把命中 cache 最长的请求排在最前，中位 TTFT 最低，但在负载尖峰下会饿死工作量昂贵的请求；先来先服务（FCFS）能约束尾部，却抬高最差情况下的中位 TTFT。Fairway 以自适应复用优先级解决这一取舍：队列短时偏向 KV 复用，当请求等待时间相对其自身 prefill 时间变长时转向公平分配；实现上采用虚拟双车道模型，在引擎等待队列之上叠加一条「KV 复用优先」的 Fast 车道与一条 Fair 车道，让便宜的复用请求能加速而不饿死昂贵请求，且无需针对具体负载调参。效果上，瞬时过载下它降低尾部 TTFT 而不牺牲中位，在各负载与工作负载上匹配或超过最佳基线，p99 TTFT 比已有前缀感知调度器最多低 8.6 倍；负载尖峰期间保持 FCFS 的尾部，同时中位 TTFT 低 6 倍。

对广域的启示：一旦把「本地命中 / 远端拉取 / 完全未命中」看成三档复用，调度问题就与广域 cache 亲和调度同构；Fast/Fair 双车道机制可以直接搬来做跨域预取的优先级骨架，避免远距离命中请求拖崩尾部时延。

7. Parallelism-Aligned Pruning and Round-Aware Context Reuse for On-Device Multimodal Agents

  • 链接：https://arxiv.org/abs/2611.02601
  • 时间：2026-11-02
  • 方向：端侧复用 · 缓存生命周期 · 结构化剪枝

摘要：端侧多模态 agent 受两类部署错配牵制：预训练注意力结构未必能被边缘加速器的计算核心数整除，产生不规则分区；而标准前缀缓存会把历史视觉 token 一直留在持久 KV cache 里，容量随交互轮次线性增长。PARC 用并行度对齐的结构化剪枝加生命周期感知的 KV cache 重组来同时应对。模型层以泰勒一阶重要性与 GQA 感知的选择，把注意力维度调整到目标核心数可整除，同时保持 query 对 key/value 的比例与 head 维度不变。运行时按生命周期把系统 prompt、持久文本历史与瞬态视觉观测分开，并在工具执行期间更新文本历史，使历史图像退出持久缓存，从而在固定预算下容纳更多交互轮次。在 2,062 个 GUI 动作上增量接口没有精度回退，任务感知的恢复训练补齐了 98.7% 的动作类型精度差距，坐标命中率回到原水平。七核部署下硬件对齐剪枝把视觉编码器时延降低 11.4%，解码吞吐提升 23.8%，每堆高水位内存降低 12.7%；参数匹配的对照实验确认提速主要来自核心对齐而非参数减少。

对广域的启示：「系统 prompt / 文本历史 / 瞬态观测」三层生命周期的划分可直接映射到广域：稳定前缀跨机房共享复用，瞬态观测留在本地并按轮次失效，避免把短命数据同步到远端。

8. Solv3R: 3D Looped Transformer as a Multi-view Solver

  • 链接：https://arxiv.org/abs/2611.02857
  • 时间：2026-11-02
  • 方向：状态缓存复用 · 迭代求解 · 三维重建

摘要：经典 structure-from-motion 是迭代式的，从当前估计不断细化相机位姿与场景几何，因此地图能自然扩张而不必重算已解视图，几何估计也能随观测增多而改进；但多数几何基础模型要么一次前向就吐出全部几何，要么只随新帧递归更新一个循环状态，使这种扩张与细化变得不自然。Solv3R 是一个 looped transformer，学习从当前状态继续求解多视图几何，其更新算子与迭代次数无关，已细化视图与新引入视图可以不论「解得多少」被联合更新。作者训练该算子在持续迭代下保持重建准确、并能纠正不准确的状态，从而同时支持对固定图片集合的细化与对新观测的整合。已解视图的表示可以被缓存一次、在后续迭代中复用为几何上下文，从而得到紧凑高效的 KV cache。论文分析了求解器动态并与现有方法比较，显示单个学习到的求解器即可覆盖离线重建、增量重建、重定位与流式四种用法，无需任务特定训练或专用模块。

对广域的启示：已解视图的表示「缓存一次、跨轮复用」与 KV 前缀复用是同构的：把远端已经算好的状态留作上下文，比每轮重算更省链路；更新算子与迭代次数解耦这一点尤其重要，意味着缓存在多次刷新之间仍保持有效。

三、系统与边缘：缓存压力下的稳定性与落地形态

9. When Cache Pressure Becomes a Trap: Metastability in Agent Serving

  • 链接：https://arxiv.org/abs/2611.02543
  • 时间：2026-11-02
  • 方向：缓存压力 · 亚稳态 · 准入控制

摘要：LLM agent 反复把不断增长的对话发给模型，前缀复用因此成为高效服务的核心。论文揭示一个被忽视的风险：短暂的流量激增会破坏这种复用，并在 prefill-decode（PD）分离引擎中触发亚稳态失效——到达量回落到引擎此前完全能承受的水平之后，服务仍持续处于退化状态。在 SGLang 上，一次十分钟的激增使随后一小时的 goodput 下降约 88%，而移除残留的突发会话后服务在几分钟内恢复。维持这种状态的机制是「种群-缓存反馈」：调用变慢会延长会话并放大其聚合上下文（working set），由此产生的缓存未命中又增加重算、进一步推迟请求离开。作者用流体模型刻画这一反馈的资源条件，解释缓存容量、工具耗时与基础负载如何影响脆弱性；在 36 个模拟部署中该模型标出了全部 17 个 cache-first 案例，受控模拟显示在其它条件不变时只改后续到达就能反转恢复结果——缓存崩塌后，低复用离开容量决定了恢复所需削减多少负载。据此构建 Basin：给每个会话固定优先级，按自适应准入预算预留其预测的峰值上下文，用空闲的 decode 显存延展缓存，并主动丢弃超额需求。在真实的 H200 1P3D 部署与激增场景（含长上下文 SWE-bench Pro 会话）中，到达时原型取得 Continuum 的 1.20–1.70 倍、单独 HiCache 的 2.35–3.59 倍 goodput；模拟中预测器驱动的策略在 6 个激增场景下达到最强基线的 1.20–2.05 倍。

对广域的启示：广域 KV 复用面对的是同一条反馈链——链路抖动让请求变慢、会话 working set 变大、跨域命中率下降、于是更慢；因此跨域 cache 准入必须按会话峰值上下文预留预算并保留应急容量，否则一次抖动会让退化持续超过一小时。

10. MedPsy: State-of-the-Art Small Medical Language Models for Efficient Edge Deployment

  • 链接：https://arxiv.org/abs/2611.02011
  • 时间：2026-11-01
  • 方向：边缘部署 · 长推理轨迹 · 量化

摘要：医疗语言模型有望提供专家级临床支持，但最强的开源大模型对私有边缘设备而言仍然过大，而紧凑的医疗小模型在知识密集任务与真实医疗任务上又明显落后。能塞进边缘显存的推理模型还会输出很长的推理轨迹，使串行解码变长，端到端时延、能耗与 KV cache 显存压力一并上升。MedPsy 用 1.7B 与 4B 两个纯文本医疗模型族来平衡精度、生成长度与效率：数据侧用覆盖生物、医学与健康的种子构建合成医疗数据管线，并以 235B 医疗教师模型产生思维链目标；后训练采用四阶段课程，前两阶段 SFT、后两阶段带难样本挖掘的强化学习；部署评测覆盖多种 GGUF 量化变体，并在笔记本与手机真机上做推理测试。七个封闭式医疗基准上，MedPsy-4B 比 MedGemma-1.5-4B 高 19.34 个点、匹敌 MedGemma-27B 而体积小 6.75 倍；MedPsy-1.7B 以不到一半的体量比 MedGemma-1.5-4B 高 11.42 个点。HealthBench-Hard 上 4B 超过 MedGemma-27B 15.33 个点，1.7B 超过 11.66 个点而体积约小 16 倍。效率侧，相对 Qwen3 backbone 平均响应长度缩短 1.7 倍（1.7B）与 3.2 倍（4B）；Q4_K_M 量化把聚合分数保持在 BF16 的 1 分以内，磁盘占用降低约 69%；真机推理中 4B 更短的生成带来中位端到端时延与单答案估计能耗降低 75%，在测试的笔记本与手机配置上峰值内存均低于 5 GB。

对广域的启示：长推理轨迹会成倍放大缓存的体积与存活时间，「把输出压短」是最上游的缓存治理手段；对跨域的启示是边缘侧应先压短生成、再做上行同步，链路预算会随之明显宽松，而低比特量化在 1 分以内的代价说明它适合作为端到边缘的传递格式。

今日观察

  1. 压缩的收益来源被拆开研究：2611.02230 用层深校准决定「谁来打分」、2611.03142 用 stride 对齐的跨层重建把 cache 减约三分之一、2611.03247 把结构冗余与精度冗余分级处理，共同说明单点阈值远不如「哪一层、哪一级」重要。
  2. 长上下文的瓶颈正从「存不下」转到「读太多次」：2611.03200 以分块摘要把 KV 读取量降到 8–16 倍更少，1M token 上核心 attention 快 11.7 倍（prefill）与 13.0 倍（decode），代价是质量-速度的显式可调。
  3. 复用研究的问题意识从「能否命中」转向「命中之后怎么排队、怎么不塌」：2611.02082 用 Fast/Fair 双车道把 p99 TTFT 压到最多低 8.6 倍，2611.02543 则量化出一次十分钟激增可让随后一小时 goodput 掉约 88%。
  4. 通信与部署成本被正式写进压缩目标函数：2611.02583 让低秩 Value 表示同时压缩缓存宽度与张量并行通信（8 卡最高 1.42 倍加速），而 2611.02601 与 2611.02011 表明端侧缓存生命周期与推理轨迹长度仍是落地形态的主导变量。
