一、重点方向：位置无关复用走到 MLA（3 篇）

1. RedKnot-MLA: Multi-Head Offline-Online Reuse for DeepSeek-V4 Long-Context Serving

  • 链接：https://arxiv.org/abs/2609.07008
  • 时间：2026-09-07
  • 方向：MLA · 位置无关复用 · RoPE 重定位

摘要：MLA 用一条 packed latent KV 流承载许多逻辑 query head，省内存但也消除了传统 head-wise 复用所假设的物理 per-head 缓存边界。本文是 RedKnot"head-aware 复用"原则在 DeepSeek-V4 上的实现：每份不可变文档先离线在 canonical position zero 处理，通过认证的 Local-head 贡献保留为 MLA-Off；服务时用 query 侧 RoPE 重定位把文档恢复到它在本次请求中的位置，一小撮 Global head 与受保护的 Local token 行重算为 MLA-Online，两条路径在一次共享输出投影之前合并，packed MLA latent 全程不拆。DeepSeek-V4-Flash 有 37 个可复用层、56/8 的 Local/Global 划分，给出 75.29% 的逻辑 head-row 解析上限；Pro-0813 配置为 55 层、112/16 heads，上限 78.89%。冻结的 Flash 工作点上，热工件 TTFT 加速 2.02–3.84×；256K 下归档的三数据集研究给出聚合 F1 +3.24 分、EM +4.16 分、主算子算术节省 78.7–79.5%，但其中一个数据集 F1 下降 2.81 分。另有作者报告的 256K 热工件 QPS 约 2.0×，因原始并发 trace 未包含在该包内，被作者标为初步而非归档证据。论文还描述了因式分解、位置修复、token-row 闭合、稀疏 MoE 支持、TP8 集成与解读这些结果所需的测量边界。

对广域的启示：这是"PIC 能不能跨域用"目前最硬的一个数据点——要传的状态是每份文档在 position 0 的 MLA latent（每 token 一份压缩 latent），不能直接搬过来用：必须在对端做 RoPE 重定位 + 少量 Global head/token 行重算，才能落到请求的真实位置。所以跨域可行，但"传过去能不能直接用"的答案是"不能，需要一次轻量位置修复"。另外它自带诚实标注：聚合涨、单集跌——正是评估方法论（2609.31415）警告的形态。

2. Factorized Context Attention: From Emulated to Native Grid Probing

  • 链接：https://arxiv.org/abs/2611.32423
  • 时间：2026-11-24
  • 方向：任意跨度读取 · 原生块稀疏 · 一次编码

摘要：模型要在一次前向里读完一本书、一小时视频或一张图；上下文增长时这一趟会变慢、掉精度并撞上窗口上限。稀疏注意力虽高效，但后两个限制仍在。Grid probing 是最近的免训练方法：对输入的短局部片段与跨步片段反复问同一个问题，从而找回精度、扩展触及范围，但每个问题都要把整个计算重做一遍（每个 span 都重新编码）。论文的洞察是：grid probing 本质上是"被模拟的注意力"——一个从模型外部用 prompt 复现出来的注意力模式，因为每次探测只是限制了问题能看到输入的哪一部分。于是提出 Factorized Context Attention（FCA）：一种免训练块稀疏注意力，把同一模式原生跑成模型自己的注意力。FCA 只把输入编码一次进 KV cache，在一次批前向里把所有 span 当作被 mask 的序列来读，并用阶梯式位置调度让每个 span 都留在训练过的位置范围内。在长视频理解、长上下文文本推理与图像接地三类任务上，FCA 以远低的成本达到 grid probing 的精度与触及范围：长视频比单趟多约 10 分、长篇小说多 9–14 分，能在上千帧的视频和四倍于窗口长度的文本里找到 needle，并且对同一输入的后继提问只需 grid probing 十分之一的时间。这一切都基于现成的冻结语言/视觉语言模型。

对广域的启示："编码一次、任意跨度读"就是非前缀复用在注意力模式层的实现——FCA 把"片段可以任意位置读"变成了一次 KV 编码 + 多次 mask 读取。跨域特别受益：一份上下文只需编码一次并同步一次，之后所有 span/问题都从这份 KV 上读，带宽只付一次。

3. AttentionIndex: Accelerating Learned Sparse Attention with a Causal Inverted-File Index

  • 链接：https://arxiv.org/abs/2611.02508
  • 时间：2026-11-02
  • 方向：稀疏索引 · 倒排路由 · 1M 上下文

摘要：DeepSeek-V4、GLM-5 等生产模型用的学习式稀疏注意力让每个 query 只关注 indexer 选出的 k 个 key，但 indexer 仍要为前缀里每个 key 打分——在 100 万 token 时，这个选择过程占 prefill 时间的一半以上。HiSA 式的"连续块两阶段选择"能降低这部分成本，但固定候选预算下召回随上下文增长而下降。AttentionIndex 用倒排文件索引把 indexer key 按相似度分簇，让每个 query 先路由到簇、再用原生 indexer 分数精排。索引在 prefill 期间构建，新 key 立即可检索，复用既有簇结构使维护成本低，并且每个 query 只暴露给它自己前缀构建出的簇（因果性）。在 GLM-5.3 与 DeepSeek-V4-Flash、100 万 token 上，AttentionIndex 的 prefill 吞吐是穷举选择的 1.3–1.8×；在与 HiSA 相差 5% 以内的吞吐下，多恢复 17.0 与 10.0 个百分点的穷举 top-k；同候选预算下长上下文基准准确率比 HiSA 最多高 18.4 个百分点。

对广域的启示：索引本身就是可分布的——倒排结构天然可分区、可远程查询。跨域场景里"选择哪些 KV"这一步可以被前置到索引层，远端只需返回候选簇，避免把整个 KV 拉回来再选。

二、稀疏注意力服务（2 篇）

4. DisSparse: Pipelined Top-$p$ Sparse Attention for Long-Context LLM Serving

  • 链接：https://arxiv.org/abs/2611.28522
  • 时间：2026-11-21
  • 方向：top-p 选择 · 流水线 · 块内稀疏

摘要：长上下文推理受 KV 内存需求限制，动态稀疏注意力只取并关注关键 token 子集来缓解。研究与部署中的主导原语是固定预算的 top-k 选择——它受欢迎是因为确定性块数与 vLLM 这类系统的静态内存分配对齐。但 top-k 不管注意力质量在 head、层、解码步之间如何分布都用固定预算，于是在"尖峰注意力"的 head 上浪费带宽、在"弥散注意力"的 head 上丢上下文。top-p（核）选择能自然适应这种变化，却因两个系统层难题而少见于生产：块数可变破坏确定性块分配，以及选择 kernel 本身比注意力还贵。DisSparse 把 top-p 稀疏注意力端到端集成进 vLLM：把块选择从调度器关键路径上解耦、用双流流水线把选择延迟藏在层计算后面、并提出单趟直方图 top-p kernel。论文还观察到块内稀疏（固定大小 KV 块里高/低重要性 token 混住导致选择预算被虚增），用由累积 prefill 注意力分数引导的 token 重定位 kernel 解决。多个模型、长中上下文基准上，DisSparse 的选择分析（块选择）比 SOTA top-p 方法快 1.17–1.80× 且精度损失可忽略，并在同内存预算下支持比稠密 vLLM 最多 8× 的 batch。

对广域的启示："选择延迟要能藏进计算" 是跨域取 KV 的前提——如果远端选择/预取不能与本地计算重叠，收益会被延迟吃掉。另外"块内稀疏导致预算虚增"提示：跨域按块传 KV 时，块粒度会决定无效传输比例，重定位/打包能显著提高有效带宽。

5. Shoonya: Zero-Socket In-Process Small Language Models for Graph Databases with Schema-Epoch KV Caching

  • 链接：https://arxiv.org/abs/2611.28502
  • 时间：2026-11-21
  • 方向：图数据库内嵌 · 版本纪元缓存 · O(1) 失效

摘要：把属性图数据库耦合到外部语言模型服务要付"三段式套接字税"：序列化开销远超微秒级的图读取、冗长 schema 的重复 prefill、以及与实时目录和多版本并发控制（MVCC）引擎脱节的盲解码。Shoonya 是从零构建的"商业上干净"（0.0% 非商用或 share-alike 数据）三模态（Python/Rust/OpenCypher）小语言模型（16.8M 至 1.07B 参数），与 shoonya-infer 协同设计——一个零依赖纯 Rust 运行时，嵌在 samyama-graph-enterprise 的地址空间内。直接持有 GraphStore 引用换来三个数据库原生原语：①版本纪元失效的 SchemaPrefixCache（基于写时复制的 PagedKvArena），把热 CPU TTFT 加速 4.91–13.68×，且 DDL 失效是 O(1)；②36μs 的列式目录与源区间 logit mask，强制合法本体标识符与原文片段；③低于 65μs 的只读 MVCC 门，在 389.8 MiB INT8 RSS 内服务 Tier-0 查询（59.8–67.9 tok/s），幻觉泄漏 0.0%。另有 rank-factorized 绑定嵌入（词表权重 −74.5%）、原子缩进 token（0/421 缩进错误）、4:1 GQA 配 2:1 跨层 KV 共享（INT8 KV 内存 −93.75%）、Warmup-Stable-Decay 训练、KnOTS SVD 合并、Step-GRPO 与 Rust Jacobi SVD 治理，保持 100% 层为重尾分布（α∈[1.88,2.20]）。

对广域的启示："版本纪元 + O(1) 失效"是跨域缓存必须的语义——schema/目录这类共享前缀一旦变更，跨域缓存要能常数时间判定失效，而不是全量校验。这篇把"缓存失效"做成了数据库的一等公民。

三、压缩与记忆（2 篇）

6. STAC++: Plug-and-Play Adaptive Spatio-Temporal Aware Cache Compression for Streaming 3D Reconstruction

  • 链接：https://arxiv.org/abs/2611.28793
  • 时间：2026-11-21
  • 方向：八叉树空间 KV · 响应感知合并 · 尾部重算

摘要：流式 3D 重建必须在有限内存下保住几何，而 STAC 的固定分辨率空间 KV cache 会随场景扩大而增长。STAC++ 是即插即用、免训练的框架，为无界场景下的长期重建压缩并复用空间记忆。自适应空间 KV 缓存（ASKC）把 KV 状态组织成八叉树，在不同区域与层上用自适应分辨率；响应感知缓存压缩（RACC）用注意力输出变化衡量并指导 KV 合并，在存储节省与几何保真之间取衡；时序上下文精化（TCR）复用缓存的中间特征、只重算一小段 backbone 后缀，用后续观测精化历史预测。集成到四个预训练流式 backbone 后，STAC++ 在长序列与大场景上降低空间内存占用同时保持有竞争力的重建质量，并能在有限计算开销下通过精化进一步提升质量。

对广域的启示："只重算一小段后缀"是跨域最小更新的正确形态——历史部分复用缓存，只有受新观测影响的后缀需要重算。配合八叉树式非均匀分辨率，跨域同步也可以只传被细化的区域。

7. Video-as-Weights: Compiling a Video Once into Parametric and Token Memory

  • 链接：https://arxiv.org/abs/2611.28221
  • 时间：2026-11-20
  • 方向：视频编译为权重 · LoRA + prefix token · 强到弱迁移

摘要：VLM 把视频表示为数千个视觉 token，造成随视频长度增长的巨大 KV cache；同时能在有限硬件上跑的小 VLM 理解视频的能力远不如大模型。现有压缩把视觉 token 缩短成简短 prompt 来省内存，但小模型仍用固定权重处理它们，补不上能力差距。论文提出 Video-as-Weights（VaW）：把视频在没看到任何问题的情况下编译一次，写入冻结"解释器" VLM 的参数记忆与 token 记忆。具体地，一个编译器 VLM 观看视频，一个权重解码器从每一层编译器层联合生成解释器的 LoRA 权重与可选的前缀 token，从而同时支持同模型编译与跨模型规模/深度的强到弱迁移。六个视频 QA 基准上，0.8B 解释器在自我编译时比完整 in-context 阅读高 1.7 分，用 9B 编译器时高 4.3 分，把上下文从最多 8,192 个视觉 token 压到 64 个前缀 token，内存比视频 KV cache 少 5.5×。生成的权重在 token 压缩之上再加 3.9 分，全层解码比逐层生成高 2.9 分。机制分析显示：有前缀 token 时，权重主要改变注意力 query 与 MLP down 投影以引导检索并存一份基线摘要；无 token 时，权重转向注意力输出投影，把视频内容直接写进残差流。

对广域的启示："把感知结果编译成权重"，跨域成本从"每请求传 KV"变成"一次传一个小的 LoRA"——这是本方向最激进的带宽优化：8,192 token 的 KV 换成 64 token 前缀 + 一组低秩权重。对广域而言，权重可以预分发、可复用，比逐请求的 KV 传输便宜得多。

四、循环模型与机密计算（3 篇）

8. Looped Models are Fast Multi-Token Predictors

  • 链接：https://arxiv.org/abs/2611.33896
  • 时间：2026-11-25
  • 方向：循环模型 · 多 token 草稿 · 无损加速

摘要：循环语言模型可以在不按比例增加唯一参数的情况下，通过调整循环次数来适配一个 token 所需的计算；这一性质已被用于自投机解码（浅循环当快速 drafter、深循环当 verifier）。论文指出：浅循环还能预测未来若干个 token，并据此大幅加速循环模型推理。他们提出 Floodgates：一种简单的自投机解码方法，在末尾附加一块 mask token，并通过低秩适配学习并行起草这些 token。七个模型、五个基准、多种 batch、贪心与采样解码下，Floodgates 在多数情形是最快的无损解码方法，最高 7.5× 加速。分析表明，这一加速来自循环模型的全深度训练——浅层 drafter 能通过以验证期间计算出的深层 prefix cache 为条件来利用全深度计算。

对广域的启示："以深层 prefix cache 为条件" 是关键机制：浅层草稿依赖深层缓存，而这份缓存在验证时已经算好。跨域版本的含义是——一次远端深层计算的产物可以被本地多次浅层复用，边际带宽接近零。

9. LoopTitan: What Does Parameter Revisit Buy a Mixture-of-Experts?

  • 链接：https://arxiv.org/abs/2611.34821
  • 时间：2026-11-25
  • 方向：循环 MoE · 消融 · 诚实负结果

摘要：循环 MoE 在不同深度上重复访问层参数，在不加参数的情况下增加有效深度。近期研究报告在匹配预算（参数、FLOPs、KV cache）下相对标准 MoE 有大幅增益，但这些增益把"参数重访"与其他设计选择（网络形状、残差缩放）混在了一起。论文问：参数重访本身带来了什么？用匹配的非重访对照，答案是几乎没有。作者认为重访只提供了一种 MoE 本来就有的自由度，即"以专家换深度"（固定参数下更多层、每层更少专家）。在匹配预算下把 SOTA 循环配方把重访放到最后做分解：非重访对照保留了全部增益——大部分来自网络形状，其余来自残差缩放；他们证明这个缩放相当于对重访层施加更小的学习率，这在 AdamW 不均匀层步长下有帮助，但在 Muon 下（层步长近乎相等）消失。超出匹配预算时（固定参数加计算）一次额外重访的收益超过把专家数翻倍，但没有重访时，等参数等计算的更深标准 MoE 在 Muon 下能拿到那份增益的 90.2%。总体结论：增益来自网络形状、优化器与额外计算，标准 MoE 都能采用。据此提出 LoopTitan-Base 作为更强的 MoE 基线，在 Muon 下不用重访或残差缩放就能匹配最强循环配方；开源 LoopTitan 与 17 个预训练模型，实验记录以 GitHub issues 公开，预测预先登记、完整探索历史保留。

对广域的启示："循环/重访带来的 KV 节省可能被高估"——如果增益其实来自网络形状与优化器，那"循环架构天然省 KV"这类论证就站不住。跨域选型时，应当把"KV 足迹"当成独立评测维度，而不是从"循环=省 KV"直接推断。这篇的预先登记与公开负结果也值得作为方法学参考。

10. HiPerfCC-StateReuse: Ciphertext Reuse for Fast Confidential GPU Data Movement

  • 链接：https://arxiv.org/abs/2611.29067
  • 时间：2026-11-21
  • 方向：机密计算 · 密文复用 · 跨实例共享

摘要：机密 GPU 提供接近原生的设备内计算性能，但 CPU 与 GPU TEE 之间经过不可信主机内存的传输需要对未改动的数据也做批量加解密。现有软件技术能重叠或并行这些操作，但保留其逐字节的 CPU 成本。复用已导出的密文本可避免这部分工作，但 GPU TEE 固件强制方向相关的加密密钥与每次传输新的初始化向量（IV），使直接复用不可能。论文提出 ciphertext rebinding：一个纯软件原语，在不改硬件的前提下实现重复与跨 GPU 的密文复用，同时保住机密性、完整性与新鲜性。具体地，它利用 GPU TEE 的 AES-GCM 认证中密文相关分量与 IV 相关分量可分离：GPU 预计算的目的密钥下的摘要让 CPU 无需处理载荷就能更新认证标签；这样 GPU 后续对保留密文的读取仍能走固件固定、软件不可改的 copy-engine 接口；再加一个 GPU 校正步补偿密钥与 IV 的差异以恢复原文。通过在不可信主机内存中保留 GPU 导出的密文，该原语避免了批量 CPU 解密与再加密，提高了 GPU 状态恢复与共享的有效带宽。作者在 HiPerfCC-StateReuse 中只用驱动与库的改动实现，结合批提交、流水 GPU 处理与 copy-engine 传输；用微基准评估传输效率与 CPU 开销，并用三个案例评估应用性能：模型切换、KV cache 卸载、跨实例缓存共享。

对广域的启示：机密计算链路上"搬状态"的瓶颈可能在 CPU 加解密而不在链路。跨域若跑在 TEE 上，密文复用（尤其跨实例共享同一份 KV 密文）能把"每字节 CPU 成本"消掉——这直接决定了加密跨域共享是否划算。

今日观察

  1. PIC 在 MLA 上确实可行，但"传过去不能直接用"：RedKnot-MLA 必须做 query 侧 RoPE 重定位 + Global head/token 行重算，才把 position-0 的 latent 落到请求位置。跨域设计要按"传输 + 一次轻量修复"来算成本。
  2. RedKnot-MLA 自曝的 −2.81 F1 是本期最重要的信号：聚合 +3.24 分掩盖单数据集退化，正对上 2609.31415 警告——MLA 上的 PIC 同样需要 meaningful subset 重测。
  3. "编码一次、任意跨度读"出现了原生实现：FCA 把 grid probing 的模拟注意力变成一次编码 + 多次 mask 读取，带宽只付一次。
  4. 激进带宽优化：把感知编译成权重：Video-as-Weights 用 64 prefix token + LoRA 替代 8,192 token 的 KV，内存少 5.5×。
  5. 循环架构的收益需要独立验证：LoopTitan 用预先登记的对照实验证明"参数重访本身几乎无增益"，提示"循环=省 KV"不能作为默认前提。
